# 作品页面改版实施计划

## 1. 目标、范围与完成定义

本计划把已确定的作品 UI 与接口设计落实为有依赖关系的实施步骤；它不改变系统边界，也不包含本轮代码修改。实施顺序固定为：共享基础 → 作品列表 → 项目/实验 → 视觉/影像 → 工具/仓库 → 全链路验收。每一步完成后均可保持已有公开作品正常访问，未完成的下一步能力不得提前暴露。

目标页面与参考图：

| 顺序 | 页面/类型 | 视觉依据 | 交付目标 |
| --- | --- | --- |
| 0 | 共享基础与后台最小闭环 | 四张图的共用导航、深色毛玻璃、信息与状态语义 | 可创建草稿、保存结构化内容、审核并安全发布 |
| 1 | `/portfolio` 列表 | [列表参考图](../design/前端页面ui设计-作品列表示例.png) | 发现、筛选、排序、分页与三类差异化卡片 |
| 2 | `/portfolio/:slug` 项目/实验 | [项目/实验参考图](../design/前端页面ui设计-作品项目实验示例.png) | 双栏项目头部、叙事正文、代码/步骤/对比与右侧事实栏 |
| 3 | `/portfolio/:slug` 视觉/影像 | [视觉/影像参考图](../design/前端页面ui设计-作品视觉影像示例.png) | 媒体优先首屏、可控播放/画廊、章节和创作笔记 |
| 4 | `/portfolio/:slug` 工具/仓库 | [工具仓库参考图](../design/前端页面ui设计-作品工具仓库示例.png) | 可搜索提示词控制台、展开、复制、资源预览与功能导航 |
| 5 | 收口与发布准备 | 四张图逐项回归 | 完整权限、性能、可访问性、迁移、回滚与视觉验收 |

完成不以“页面能显示”判定，而以以下条件共同成立判定：真实公开数据能驱动页面；每类作品仅显示适用能力；管理端可完成创建、审核、发布与撤回；公开接口不泄露草稿或私有资源；桌面和移动端均与参考图的层级和构图一致。

## 2. 实施总原则与前置约束

### 2.1 权威来源和职责划分

- [x] 页面结构、视觉层级、类型差异、移动端和可访问性：以 [前端页面ui设计-作品.md](../design/前端页面ui设计-作品.md) 为准。
- [x] 数据模型、DTO、接口、媒体安全、后台工作台和发布状态机：以 [作品页面改版接口与后台设计.md](../design/作品页面改版接口与后台设计.md) 为准。
- [x] 实施出现设计稿未覆盖的新交互时，先补充上述设计文档，再编码；不在页面组件中临时发明未记录的区块或接口字段。

### 2.2 不可跳过的共享约束

1. 公开读接口始终只返回 `status=published AND reviewStatus=approved` 的作品及其已就绪公开关联项。
2. 管理写操作遵循：认证 → `requireAdmin` 授权 → 输入/URL 校验 → service → 审计日志 → 统一响应；前端隐藏不是权限控制。
3. 所有媒体通过受控资产记录引用，不直接将本地路径、`storageKey` 或任意外网地址存入公开 DTO。
4. 所有三类作品共用 `PortfolioHeader`、项目事实、资源链接、相关推荐和响应式/可访问性基础；专属内容以受控区块和专属渲染器扩展。
5. 每个阶段只在所依赖的数据、接口、管理编辑能力和测试同时具备后才对公开页面启用；采用 feature flag 或类型级降级渲染保护迁移期内容。

### 2.3 阶段门禁

| 阶段 | 开始条件 | 结束门禁 |
| --- | --- | --- |
| 0 | 当前 `Portfolio` 仍为字符串字段模型 | 新迁移、DTO、管理员草稿与发布门禁通过验证；至少一条迁移样本可在预览中渲染 |
| 1 | 0 完成，存在至少三种类型的已发布样本 | 列表分页/筛选由后端执行，URL 可复现状态，卡片无类型混淆 |
| 2 | 1 完成，存在项目/实验样本和公开媒体 | 项目详情可独立发布并在未使用影像/工具区块时不出现空面板 |
| 3 | 2 完成，视频/图片媒体链路已就绪 | 影像详情不自动播放、画廊可访问、媒体失败可回退 |
| 4 | 2 完成，提示词条目数据与服务端检索可用 | 工具详情在不下载全量正文的情况下完成分类、搜索、展开和复制 |
| 5 | 1–4 均完成 | 权限、迁移、性能、可访问性和四张图的视觉回归全部通过 |

## [x] 3. 阶段 0：共享数据、接口与管理最小闭环

### 3.1 工作范围

- [x] 新增 `Portfolio` 的 `type`、访客展示状态、时间/角色/技术栈、版本与归档字段，以及 `PortfolioMedia`、`PortfolioResource`、`PortfolioBlock`、`PortfolioPromptEntry`、`PortfolioPromptTag`。
- [x] 为区块、媒体、资源、提示词和公开 DTO 建立共享枚举与 Zod 判别联合校验；不接受未定义的 `kind` 或自由 JSON。
- [x] 新建 `portfolio-service`，将 Prisma 读取、公开投影、状态转换、资源白名单、发布检查和管理写入集中在 service 层。
- [x] 建立管理员最小 API：创建/读取/保存作品草稿、上传或关联受控媒体、送审、审核、发布、撤回、归档、认证预览；每个写操作写入审计日志。
- [x] 新增 `/admin/portfolio` 最小工作台：作品状态列表、新建草稿、进入编辑、预览、送审和审核/发布操作。首期编辑器可先提供基础字段、封面、资源和通用 `richText` 区块，类型专属编辑面板随阶段 2–4 补齐。
- [x] 改造内容流水线：`contentType=portfolio` 的候选审核通过后仅创建作品草稿，不直接公开；在后台显示为“已创建作品草稿”。

### 3.2 数据迁移与兼容

- [x] 迁移前备份 SQLite；新增 Prisma migration 后执行 `prisma validate`、迁移部署验证和回填计数核对。
- [x] 旧记录默认回填为 `type=project`；`coverImage` 转受控封面媒体、`link` 转资源、`content` 转清洗后的 `richText` 区块、旧标签迁入规范化结构。
- [x] 旧字段仅用于一次性迁移回填；新代码不再读取旧字段或保留运行时回退，回填完成后删除旧列。
- [x] 回滚只回退读取和页面开关，保留新表及其数据；不得通过删除迁移丢失新建作品、媒体或审核历史。

### 3.3 阶段验收

- [x] 未登录用户请求所有 `/api/admin/portfolio/**` 得到拒绝；管理员写入具有审计记录。
- [x] 草稿、送审、要求修改、批准、发布、撤回、归档分别在管理列表、认证预览和公开接口中显示/隐藏正确。
- [x] 公开 DTO 不含本地路径、`storageKey`、审核意见、草稿区块、未就绪媒体或提示词正文。
- [x] 迁移后的项目样本可用新 DTO 渲染；旧数据回退不产生 500 或破损封面。

## [x] 4. 阶段 1：作品列表 `/portfolio`

### 4.1 参考图还原目标

按列表参考图实施“悬浮导航 → 左对齐标题区 → 单条筛选台 → 三列作品网格”。标题区显示 `PORTFOLIO ARCHIVE`、作品标题、简介和已发布数量；右侧仅保留静态环境标记。筛选台内按顺序展示搜索、类型切换、年份、排序和结果计数，不能退化为多块无关联的表单。卡片使用统一 16:9 封面和深色毛玻璃，但项目、影像、工具分别露出技术/过程、媒体/时长、复制/搜索等不同能力线索。

### 4.2 后端与数据计划

- [x] 将 `GET /api/portfolio` 改为参数化分页接口：`q/type/media/tag/year/sort/page/pageSize`；在数据库/服务层完成过滤与排序。
- [x] 返回 `items + pagination + filters`；`filters` 只聚合当前可公开的类型、媒介、年份和标签。
- [x] `PortfolioListItem` 仅返回卡片所需字段、受控封面 URL 和由公开数据计算出的能力枚举；不加载详情区块、提示词全文或管理字段。
- [x] 固定默认排序为“精选、手工顺序、最近发布”，其余排序使用稳定次序；无真实统计数据时不实现热度排序。

### 4.3 前端与后台计划

- [x] 前端将当前一次性 `useFetch('/api/portfolio')` 替换为响应 URL query 的数据请求；搜索输入防抖，但 URL 写入和清除筛选必须立即、可回退。
- [x] 构建类型卡片展示映射：`project`、`visual`、`tool` 各自的角标、能力文案、缺省封面和日期/媒介摘要；卡片主体维持单一 `NuxtLink` 语义，独立外链不得嵌套。
- [x] `>=1100px` 三列、平板两列、`<=760px` 单列；筛选变为折叠/抽屉，触控目标不小于 44px。
- [x] 后台列表增加缩略图、类型、发布状态、审核状态和精选标识；管理员可在基础编辑器设置列表必需字段，不能发布缺封面/标题/type/slug 的作品。

### 4.4 阶段验收

- [x] 同一查询链接刷新、复制、后退/前进均得到相同筛选和分页结果。
- [x] 三种类型卡片在同一页混排时可一眼区分，封面缺失使用类型占位而非破损图片。
- [x] 公开列表仅显示已发布且已审核记录；空态与接口失败不泄露内部错误。
- [x] 对照参考图检查导航居中、筛选台完整性、卡片 16:9 比例、三列间距和冰青选中态；移动端无横向页面滚动。

## [x] 5. 阶段 2：项目 / 实验详情

### 5.1 参考图还原目标

按项目/实验参考图构建“文本信息约 42% + 预览媒体约 58%”的项目头部。左侧依次为类型、标题、摘要、角色/周期/技术事实和明确主操作；右侧为真实项目预览。下方采用宽主内容和固定/粘性右栏：主栏组织项目背景、设计与实现、步骤线、代码和前后对比；右栏只显示项目事实、资源和当前章节导航。

### 5.2 后端与数据计划

- [x] 完成 `GET /api/portfolio/:slug` 的 `project` 投影：基础事实、主操作、资源、已发布媒体、排序后的 `richText/timeline/code/comparison/imageGallery` 区块与最多三条相关推荐。
- [x] 为区块定义严格校验：代码必须有语言和文件名；比较区块必须成对引用可公开媒体；锚点在单作品中唯一；嵌入演示只允许白名单域名。
- [x] 发布检查：项目必须有标题、摘要、类型、封面或合规预览媒体、至少一个项目叙事区块，以及可选但至多一个主操作。

### 5.3 前端与后台计划

- [x] 新建 `ProjectDetail` 渲染器和共享详情壳；根据区块类型显示步骤线、代码复制、图片对比、资源卡，不使用大段 `v-html` 代替区块渲染。
- [x] 代码复制成功以可见文字与 `aria-live` 反馈；代码/表格只在自身容器横向滚动；比较区块在窄屏改为纵向。
- [x] 右侧目录由有锚点的公开章节生成；短项目或无章节时整栏不出现空占位。
- [x] 管理编辑器新增项目区块库、拖拽排序、代码/对比媒体选择、资源主操作选择和发布检查提示。

### 5.4 阶段验收

- [x] 项目详情与影像、工具数据严格隔离；项目页面不出现提示词控制台或影像播放控件。
- [x] 项目头部、右侧事实栏、01/02/03 步骤线、代码与 Before/After 对比的层级与参考图一致。
- [x] 未白名单嵌入、缺 `alt` 媒体、未就绪封面或不完整比较区块阻止发布。
- [x] 键盘可使用返回、资源、目录和复制功能；缩窄到移动端后内容不溢出且右栏变为概览/目录折叠区。

## [x] 6. 阶段 3：视觉 / 影像详情

### 6.1 参考图还原目标

按视觉/影像参考图先展示近全宽 16:9 主画面或视频 poster，再将类型、标题、简短说明、年份、媒介、时长和“播放作品”放入画面下缘的低透明信息带。主内容为左侧影像章节/画廊和简短创作笔记，右侧为作品信息、资源和章节目录。页面的视觉中心永远是实际媒体，不以厚重开发面板或长文本夺走注意力。

### 6.2 后端与数据计划

- [x] 扩展详情投影的 `visual` 分支：主媒体、poster、时长、字幕/替代说明、排序章节、画廊媒体、地点/创作时间/角色、资源和短创作笔记。
- [x] 媒体状态只允许 `ready` 项进入公开详情；视频/GIF 必须有 poster，图片必须有 alt、宽高，视频需要时长和可访问说明。
- [x] 如单个影像作品的媒体数量超过详情载荷上限，新增 `GET /api/portfolio/:slug/media?page&pageSize`，仅分页返回该作品的已公开媒体；首屏仍由详情接口返回主媒体和首批章节。
- [x] 管理上传处理 MIME、文件大小、尺寸/时长、缩略图生成和失败状态；只有派生图/海报就绪后才允许发布引用。

### 6.3 前端与后台计划

- [x] 新建 `VisualDetail` 渲染器，媒体首次仅加载 poster；播放、GIF 动态和全屏画廊均由用户显式触发，切换/关闭可键盘操作。
- [x] 章节缩略图显示编号、标题和时长；失败时回退到 poster、alt 和明确“打开资源”链接，不显示空白播放器。
- [x] 影像笔记保持短、可读，不在首屏堆积项目技术细节；右侧信息按字段存在情况呈现。
- [x] 管理编辑器新增主媒体选择、poster 关联、章节排序、图注/alt、时长/地点/角色以及媒体就绪检查。

### 6.4 阶段验收

- [x] 影像页首屏、信息带、三列章节缩略图和右侧作品信息与参考图一致；没有项目代码面板或工具搜索栏。
- [x] 页面打开时视频/GIF 不自动播放或自动带声；`prefers-reduced-motion` 时保持静态 poster。
- [x] 全屏画廊有焦点管理、Esc 关闭、前后切换、alt/图注；所有媒体加载失败均有可访问回退。
- [x] 移动端媒体全宽、章节纵向或横向可控浏览，页面根节点无横向溢出。

## [x] 7. 阶段 4：工具 / 仓库详情

### 7.1 参考图还原目标

按工具仓库参考图构建“左标题/用途 + 右项目信息”的头部，下方为深色毛玻璃功能控制台。控制台包含介绍/提示词/资源标签页、分类 chips、搜索框和提示词条目；右侧为功能导航和资源预览。访问者进入后应立即检索、展开和复制，不应先穿过普通长文。

### 7.2 后端与数据计划

- [x] 详情接口对 `tool` 只返回工具壳、分类摘要、条目数、资源和首屏必要信息，不返回全部提示词正文。
- [x] 新增 `GET /api/portfolio/:slug/prompt-entries?q&category&tag&page&pageSize`：仅服务 `type=tool AND toolMode=prompt_vault` 的公开已审核条目，服务端检索标题、摘要、标签和正文，但列表只返回分页摘要。
- [x] 新增 `GET /api/portfolio/:slug/prompt-entries/:entrySlug`，在用户展开单项时按需返回正文、变量、示例与风险提示；两个端点同样执行父作品和条目的公开状态过滤。
- [x] 管理端的嵌套保存校验 `PromptEntry` 标题、分类、正文、变量 JSON、风险等级、标签与排序；发布检查要求至少一个已审核公开条目。

### 7.3 前端与后台计划

- [x] 新建 `ToolDetail` 与 `PromptVault` 渲染器。当前 tab、分类、搜索词、页码和已展开条目写入 URL query/hash，以支持分享、刷新和浏览器导航。
- [x] 每个条目默认只显示标题、场景摘要、标签和“展开提示词”；展开后显示保留换行的等宽正文、变量说明和明确的复制按钮。
- [x] 复制反馈为“已复制”文字状态与 `aria-live`，不可只变更图标；“保留变量”和“清洁版本”如同时存在，必须分为两个明确操作。
- [x] 管理编辑器新增工具模式开关、提示词分类与条目编辑、变量结构验证、示例/风险提示、资源预览和发布前条目计数。

### 7.4 阶段验收

- [x] 工具页面在第一屏可见搜索与分类，布局、控制台标签页、右侧功能导航和资源预览与参考图对应。
- [x] 搜索、分类、分页和展开均由 URL 与服务端结果驱动；不会把整库正文下载到首屏。
- [x] 复制、展开、收起、键盘焦点和移动端触控均可用；提示词正文保留换行且页面不横向溢出。
