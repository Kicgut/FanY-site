# 前端页面 UI 设计：作品档案与作品详情页

## 1. 目标与范围

作品页面是个人创作档案，不是只有封面、标题和外链的作品集。它应支持项目介绍、富文本过程记录、图片与相册、视频/GIF、代码片段、项目链接、交互演示、提示词仓库、资料下载和结构化元数据。

页面需与首页和文章页共享深海军蓝、低对比度天体环境层、冰青强调色、细边框及深色毛玻璃材质；作品页不使用首页的完整人物/平原电影场景，以保证项目内容、媒体和操作工具处于视觉中心。

本设计覆盖：

- `/portfolio`：作品发现、分类、筛选与作品卡片。
- `/portfolio/:slug`：作品详情、富媒体内容与功能型作品界面。
- 以“提示词仓库”为例的可复制、分类、搜索和展开交互。

## 1.1 作品类型与详情页模式

作品不应按技术名词无限拆分。公开站只维护三种可理解、可扩展的展示模式；`category`、标签、技术栈和媒介用于细分内容，而不是继续增加页面类型。

| 作品类型 | 适用内容 | 详情页主布局 | 核心交互 |
| --- | --- | --- | --- |
| **项目 / 实验** | 网站、应用、开发实验、研究过程、图文案例 | “项目头部 + 正文过程 + 右侧事实/目录” | 阅读过程、查看代码、打开演示、查看资源 |
| **视觉 / 影像** | 摄影组图、视频、动态视觉、短片、视觉实验 | “沉浸式首图/播放器 + 画廊时间线 + 简短创作说明” | 查看媒体、播放/暂停、进入全屏、切换组图 |
| **工具 / 仓库** | 提示词仓库、模板库、小型实用工具、资料集合 | “功能控制台 + 使用说明 + 条目/结果列表” | 搜索、筛选、复制、展开、下载或跳转 |

三者共享顶部导航、深色毛玻璃材质、标题区、项目事实与资源语义；仅主内容区随类型变化。这样访客在列表页即可预期进入后是“阅读项目”“浏览影像”还是“直接使用工具”。

## 2. 当前实现与 UI 不足

当前作品列表页位于 `nuxt-app/pages/portfolio/index.vue`，详情页位于 `nuxt-app/pages/portfolio/[id].vue`。现有实现具备发布状态过滤、封面、标题、描述、标签、Markdown 内容和一个外部链接入口，但只适合基础静态项目展示。

### 2.1 作品列表不足

- 列表使用浅色背景、白色卡片和暖棕色强调，与首页及文章页已确定的深色毛玻璃系统不一致。
- 所有作品卡片结构相同，无法区分“项目 / 实验 / 提示词仓库 / 视频作品 / 图文案例 / 工具”等作品类型。
- 缺少搜索、分类、标签、年份、媒介类型与排序，作品增加后难以发现。
- 卡片只展示封面、标题、描述和标签，没有项目状态、媒介、技术栈、角色、更新时间、可交互能力或外部资源等信息。
- 封面图片未规定固定尺寸、懒加载与缺失封面策略，长列表可能出现布局偏移和视觉破损。

### 2.2 作品详情不足

- 详情页是单列标题、封面、Markdown 正文和外链，缺少项目概览、章节导航、项目元数据、媒体资源、相关作品和下一步操作。
- Markdown 渲染只提供基础富文本，尚未定义代码复制、语言标记、视频/GIF、图片图注、对比图、嵌入演示、下载文件和提示词块等能力。
- 外链仅以“访问相关链接”展示，不能区分在线演示、源码、视频、文档、下载或项目主页。
- 缺少对富媒体加载、外部嵌入白名单、隐私边界、移动端横向溢出和减少动态效果的约束。
- 现有 Portfolio 模型只有 `content`、`images`、`link`、`tags`、`category` 等字符串字段；它不能可靠表达多媒体资源、多个操作、结构化项目事实或提示词仓库条目。

## 3. 设计原则

1. **作品是可探索的内容单元**：访客先理解作品做了什么、属于什么类型、当前状态和可以做什么，再决定是否深入。
2. **内容与功能同等重要**：富文本讲述背景与过程；代码、媒体、提示词和演示提供可操作的证据。
3. **功能按需出现**：静态摄影作品不展示代码工具栏；提示词仓库不伪装成普通长文；不同作品类型只呈现相关操作。
4. **可复制但不失控**：复制提示词、代码和链接应有清晰反馈；公开页面不提供执行 shell、写入配置或访问私密数据的能力。
5. **媒体克制加载**：视频、GIF、嵌入演示和高分辨率图片应以封面、点击播放、懒加载和尺寸约束控制性能。

## 4. 作品档案列表页（`/portfolio`）

### 4.1 页面结构

桌面端在 `min-width: 1100px` 时采用“标题区 + 筛选条 + 作品网格”结构：

```text
固定顶部悬浮导航
└── 作品档案标题区（PORTFOLIO ARCHIVE / 作品 / 简介 / 总数）
    ├── 分类与搜索筛选条
    ├── 精选作品横幅（可选，最多 1–2 项）
    └── 作品网格（3 列，按类型混排）
```

标题区左对齐，显示 `PORTFOLIO ARCHIVE`、主标题“作品”、一句说明和已发布作品总数。右侧可保留小型静态蔚蓝地球环境标记，但不显示小猫跨卡片动画。

### 4.2 筛选与分类

筛选状态必须同步到 URL 查询参数，支持刷新恢复、复制链接和前进/后退。

- 搜索：标题、简介、标签、技术栈与作品类型。
- 类型：全部、项目 / 实验、视觉 / 影像、工具 / 仓库。
- 媒介：图文、代码、图片、视频、GIF、交互演示；只在有对应数据时显示。
- 标签：常用标签可多选，过多时折叠为“更多标签”。
- 年份与排序：最新更新、最新发布、精选优先；无真实统计数据时不展示热度排序。
- 清除筛选：仅在筛选生效时显示，并同时显示结果数量。

### 4.3 作品卡片

作品网格使用 3 列毛玻璃卡片；卡片以明显类型标识、封面比例与能力摘要区分三种模式：项目 / 实验显示技术与过程，视觉 / 影像显示媒体数量或时长，工具 / 仓库显示“可复制”“可搜索”等能力。它们仍遵循统一的信息优先级：

1. 封面、视频 poster 或作品预览图，固定 16:9 比例；无封面时显示低对比度类型封面，不显示破损图片。
2. 类型标识，例如 `PROJECT`、`PROMPT VAULT`、`VISUAL LOG`、`EXPERIMENT`。
3. 作品标题与最多两行简介。
4. 媒介/能力图标或文本，例如“代码”“视频”“可复制提示词”“在线演示”；装饰图标需要 `aria-hidden`，操作图标必须有名称。
5. 最多 3 个技术或主题标签、更新时间与精选状态。

卡片整体使用链接语义进入详情页；若卡片内需要“在线演示”等独立外链，外链必须在卡片内部作为单独链接，避免嵌套链接。卡片悬停与键盘聚焦只增加边框亮度、轻微上浮和媒体遮罩透明度，不使用自动播放视频。

## 5. 作品详情页（`/portfolio/:slug`）

### 5.1 页面结构

详情页使用“作品头部 + 内容工作台 + 文末延伸”的结构。桌面端在内容复杂时使用主内容栏和右侧项目导航栏：

```text
固定顶部导航
└── 面包屑 / 返回作品档案
    ├── 作品头部：类型、标题、简介、状态、项目事实、主要行动
    ├── 主内容：富文本、媒体、代码、提示词或交互模块
    └── 右栏：项目目录、资源链接、章节/功能导航
```

项目头部左对齐，包含类型、标题、简介、封面或预览媒体、角色、时间范围、状态、技术栈、主题标签与主要操作。主要操作根据作品类型变化，例如“访问在线作品”“查看源码”“播放演示”“浏览提示词”。

外部动作使用明确文案，不使用笼统的“访问相关链接”。外部链接必须带 `target="_blank"` 与 `rel="noopener"`，并说明目的地，例如“打开在线演示 ↗”“查看 Git 仓库 ↗”“观看演示视频 ↗”。

### 5.2 富文本与媒体模块

作品详情的 `content` 不应只视为普通 Markdown。渲染层应支持受控的内容块：

| 内容块 | 展示与交互要求 |
| --- | --- |
| 项目叙事 | 标题、段落、引用、关键结果与图文过程；保持舒适阅读列宽 |
| 图片/画廊 | 固定尺寸、alt、图注、懒加载；支持 1/2/3 列画廊与全屏查看 |
| 视频 | 使用 poster、时长和点击播放；默认不自动播放，提供字幕/说明与减少动态效果策略 |
| GIF/动效 | 默认首帧或静态 poster；用户点击后播放，提供暂停；避免多个 GIF 同时循环 |
| 代码块 | 语言、文件名、复制按钮、横向滚动、行号可选；复制后以 `aria-live="polite"` 反馈 |
| 对比/流程 | 并排前后对比、时间线或步骤卡；移动端转为纵向堆叠 |
| 下载资源 | 文件名、格式、大小、用途与下载链接；不得暴露本地真实路径 |
| 外部嵌入 | 仅允许白名单来源；使用 sandbox、懒加载、明确“打开演示”回退链接 |

富文本允许更丰富的视觉节奏，但正文、媒体与代码不得被背景装饰、地球组件或自动小猫动画遮挡。

### 5.3 项目事实与资源栏

作品头部或右侧栏提供结构化项目事实，字段按实际存在情况显示：

- 状态：进行中、已完成、归档或实验。
- 时间：开始、完成或最后更新日期。
- 角色：个人创作、设计、开发、摄影等。
- 技术与媒介：Nuxt、Vue、TypeScript、Shader、摄影、视频等。
- 资源：在线演示、源码、文档、视频、下载、相关文章。

字段缺失时不显示空占位。复杂项目的右栏提供“项目概览 / 过程 / 媒体 / 资源 / 相关作品”锚点导航；短作品不强行显示目录。

### 5.4 三种详情页的差异化布局

#### 项目 / 实验：叙事型项目档案

适用于需要说明问题、方案、过程与结果的作品。首屏以项目标题、短摘要、项目事实、封面或可播放演示组成双栏；下方按“背景 / 方案 / 过程 / 结果”阅读流展开。代码、流程、前后对比和资源块嵌入相应章节，右侧只在长内容时显示目录与资源链接。主行动最多一个，例如“打开在线演示”。

#### 视觉 / 影像：媒体优先的观看页

适用于照片系列、影像记录和动态视觉作品。首屏使用 16:9 主画面或视频 poster，标题和拍摄/创作信息压在媒体下方的低透明信息带中；不在首屏堆叠长段落。下方先呈现可控画廊或视频章节，再以短小的创作笔记、地点/年份/媒介信息收束。图片可全屏查看，视频由用户点击播放；GIF 默认静态首帧。避免把摄影作品误做成开发文档。

#### 工具 / 仓库：直接可用的功能页

适用于提示词仓库、模板库和可检索资料。标题区说明用途、条目数量、更新日期和使用提醒；紧接着放置搜索与分类控制，主要区域直接显示条目和明确操作。说明文放在功能区之前或折叠于“使用说明”，不能让用户滚过长篇介绍才获得复制或搜索能力。提示词仓库即采用此模式。

## 6. 功能型作品：提示词仓库

提示词仓库是作品详情中的一种专属模式，不使用普通 Markdown 长文替代功能界面。它由“说明区 + 分类与搜索 + 提示词列表”构成。

### 6.1 页面内容

- 顶部说明：仓库用途、适用模型或场景、最后更新时间、条目数量和使用提醒。
- 分类：例如写作、编程、图像、研究、工作流；分类状态同步到 URL。
- 搜索：按标题、用途、标签和提示词正文检索；搜索输入有可见标签或 `aria-label`。
- 提示词条目：标题、场景说明、标签、可折叠提示词正文、变量说明、更新时间和复制按钮。
- 可选示例：输入/输出案例、使用技巧、风险提示和相关提示词。

### 6.2 提示词条目交互

每个条目使用独立的深色毛玻璃卡片：

1. 默认显示标题、用途、标签和简短摘要。
2. 点击“展开提示词”后显示等宽正文、变量说明和复制按钮；展开状态映射到 URL 查询参数或 hash。
3. “复制提示词”是明确的 `<button>`，带图标与文字；复制成功显示“已复制”并通过 `aria-live="polite"` 通知，不得只改变图标。
4. “复制并保留变量”与“复制清洁版本”等行为若存在，必须用明确文案区分。
5. 不提供远程执行、上传私密数据或自动写入系统提示词的能力。

提示词正文需要保留换行、代码、占位变量和长文本；对窄屏使用横向可滚动的等宽容器或自动换行切换，页面主体不得横向溢出。

## 7. 数据与实现边界

当前 Portfolio 模型不足以支持完整设计。后续实现如新增字段，必须提供 Prisma migration、验证方式和回滚说明。建议通过结构化字段或受控 JSON 记录以下内容，而不是继续将全部信息堆入逗号分隔字符串：

- `type`、`status`、`publishedAt`、`updatedAt`、`roles`、`techStack`。
- 多媒体资源列表：`kind`、`url`、`poster`、`alt`、`caption`、`width`、`height`、`duration`。
- 行动资源列表：`label`、`kind`、`url`、`external`。
- 受控内容块：代码、画廊、视频、提示词仓库、下载资源、嵌入演示。
- 提示词条目：标题、正文、分类、标签、变量、说明、风险等级和可见性。

所有公开 API 仅返回已发布且审核通过的作品及其公开资源。资源 URL 必须通过白名单或受控存储解析，禁止返回私有照片、未发布内容、本地路径、密钥、内部日志或未审核提示词。

## 8. 移动端设计

在 `max-width: 760px` 时：

- 作品列表改为单列卡片；筛选进入底部抽屉或折叠区，触控目标至少 44px。
- 详情页仅保留单列主内容；项目事实与资源栏折叠为标题下的概览面板。
- 作品头部标题为 30–36px；媒体全宽展示，图片画廊从多列变为单列或横向滑动。
- 视频和 GIF 仅在点击后播放；不使用自动播放、自动带声或多媒体并发播放。
- 代码、提示词正文和表格各自使用可横向滚动容器；页面根容器不得产生横向滚动。
- 提示词仓库的分类、搜索和复制按钮固定保持可见；复制按钮占满可触控区域并提供成功反馈。
- 地球组件缩小为静态环境标记或隐藏；小猫跨内容动画默认关闭。

## 9. 可访问性、性能与验收

- 提供跳到正文链接、语义化 `main`、`article`、`section`、`aside`、`figure`、`figcaption` 和可访问标题层级。
- 所有图片有 alt；装饰图片使用空 alt；图片提供宽高并在非首屏懒加载。
- 所有复制、播放、筛选、展开、查看媒体等操作使用 `<button>`、可键盘操作，并具有 `:focus-visible` 状态。
- 筛选、标签、排序、展开状态和分页反映到 URL；长列表使用分页、加载更多或 `content-visibility`。
- 视频/GIF/嵌入资源按需加载；外部嵌入有可访问的替代链接。
- 所有动效尊重 `prefers-reduced-motion`；仅动画 `transform` 和 `opacity`。

验收时至少确认：作品类型可区分；静态与功能型作品都能被正确展示；提示词可复制且有反馈；富媒体不自动干扰阅读；移动端无横向页面滚动；公开页面不暴露未审核或私有资源。
