# 前端页面 UI 设计：文档阅读页

## 1. 目标与范围

本文定义公开站的文章、技术文档和 Markdown 详情页的阅读体验，主要对应当前 `/blog/:slug` 路由。目标是在不牺牲长文阅读、代码阅读和移动端可用性的前提下，与首页的“深空电影感数字艺术 × 个人内容档案”保持同一套视觉语言。

文档页不复用首页的完整电影场景：阅读是主任务，背景只保留低对比度的深蓝灰渐层、稀疏星点、模糊天体弧面或极弱雾气，不能使用人物、地平线或大面积动态背景干扰正文。

## 2. 当前实现与 UI 不足

当前实现位于 `nuxt-app/pages/blog/[...slug].vue`，页面由居中标题、日期/阅读时间、标签、Markdown 正文及底部“返回博客列表”组成。它已经具备基础内容渲染能力，但尚未形成适合技术文档和长文的阅读结构。

### 2.1 信息架构不足

- 仅在正文末尾提供返回入口；读者进入文章后缺少面包屑、文章分类和回到上级内容的即时路径。
- 没有目录（TOC）、章节锚点、阅读进度或当前章节提示，长文与技术文档难以快速定位和跳转。
- 没有上一篇/下一篇、相关文章或同标签推荐，阅读结束后缺少自然的内容延续。
- 标题、描述、元数据和标签均集中在一个居中区块，信息层级较平，无法体现“文章 / 技术文档 / 项目复盘”等内容类型差异。

### 2.2 视觉与内容呈现不足

- 当前页面使用浅色变量与普通白色正文容器，与已确定的深色毛玻璃首页语言不一致。
- Markdown 正文的标题、引用、代码、表格、图片均为基础样式，缺少文档阅读所需的层级、留白、注释块和代码上下文。
- 正文最大宽度为 800px，但没有配合桌面端目录栏和侧边上下文；在大屏上留白未被有效利用。
- 文章标题居中是通用博客形式，但对技术文档、设计说明和项目复盘的扫描效率较低。
- 文章图片没有明确的图注、全宽展示规则、加载尺寸约束和与正文宽度的关系。
- 表格没有外层横向滚动容器；窄屏或含长代码字段的表格容易溢出。

### 2.3 交互、可访问性与移动端不足

- Markdown 标题没有锚点链接，也没有 `scroll-margin-top`，固定导航会遮挡跳转后的章节标题。
- 页面没有跳到正文的 skip link，键盘用户需要逐项经过顶部导航。
- 当前详情页没有独立的移动端排版规则；目录、图片、表格、代码块和底部导航在小屏上缺少明确降级方案。
- 图片通过 Markdown 直接渲染，尚未规定显式尺寸、懒加载策略和缺失图片状态，可能造成布局偏移。
- 加载和 404 状态使用基础组件，但没有与文档页结构一致的骨架、恢复路径和错误提示。

## 3. 设计原则

1. **阅读优先**：背景、地球组件和动效只提供环境感，任何时刻都不得压过标题、正文、目录、代码和表格。
2. **可扫描**：读者应在 3 秒内理解内容类型、主题、预计阅读时长、所在位置和可跳转章节。
3. **长文可定位**：每个二级、三级标题可深链；目录、阅读进度与章节高亮共同帮助读者恢复阅读位置。
4. **技术内容可信**：代码、命令、引用、警告、表格和图片必须有稳定、可复制、可横向滚动的呈现方式。
5. **风格统一但背景降噪**：继承首页的深海军蓝、冰青提示色、细边框和毛玻璃材质，但不使用首页的大型叙事场景。

## 4. 桌面端页面结构

桌面端在 `min-width: 1100px` 时采用“三栏阅读工作台”，最大内容宽度约 1280px：

```text
固定顶部悬浮导航
└── 页面上下文区（面包屑 / 类型 / 阅读状态）
    └── 左栏：返回文章、阅读进度、文章操作
    └── 中栏：文章头部、正文、文末延伸内容
    └── 右栏：目录、当前章节高亮、章节进度
```

### 4.1 顶部导航

沿用首页的深色半透明悬浮毛玻璃导航：左侧为 `FY / ARCHIVE`，中部为“首页 / 文章 / 作品 / 影像 / 关于”，右侧为声音、状态与账户入口。进入文章详情时，“文章”保持冰青细下划线高亮。

导航下方不再铺设复杂背景图，仅保留深蓝灰环境层和低对比度天体弧面。`<html>` 使用深色 `color-scheme`，并使浏览器主题色、滚动条和原生控件与页面背景一致。

### 4.2 页面上下文与文章头部

页面内容从导航下方约 48–72px 开始。文章头部左对齐，位于主栏顶部：

- 面包屑：`文章 / 分类或标签 / 当前标题`；当前标题可截断，但前两级必须可点击返回。
- 类型标识：例如 `FIELD NOTE`、`TECHNICAL NOTE`、`PROJECT LOG`，使用冰青等宽小字，不强制显示英文。
- 主标题：使用 44–56px 的浅灰白标题，宽度控制在约 14–18 个汉字或 32–40 个英文字符，采用平衡换行。
- 摘要：若文章有 description，则在标题下显示 1–3 行蓝灰色摘要；没有摘要时不留空白占位。
- 元数据：发布日期、更新时间（存在时）、预计阅读时间、字数或内容类型，以低对比度文本和分隔点呈现；日期必须由 `Intl.DateTimeFormat` 格式化。
- 标签：使用低对比度玻璃标签，标签过多时先显示有限数量，并提供“全部标签”展开按钮。

文章头部与正文之间使用细边框或低亮度渐隐线分隔，不使用大面积卡片包裹整篇正文。

### 4.3 左侧阅读工具栏

左栏宽度约 160px，在文章头部下方吸附于可视区域：

- “返回文章”文字链接，带左箭头，不使用孤立图标按钮。
- 细长的阅读进度轨道与百分比；进度变化仅改变 `transform` 或 `opacity`。
- “复制链接”按钮，复制成功后通过 `aria-live="polite"` 给出短提示。
- 可选的“阅读设置”入口：字号增减、衬线/系统字体切换或行距模式必须保存在本地，且默认值保持简洁。

工具栏不能遮挡正文，也不能强制显示用户不需要的社交分享控件。

### 4.4 右侧目录栏

右栏宽度约 220px，显示由 Markdown 的 `h2` 和 `h3` 自动生成的目录：

- 目录标题为“本文目录”或简洁的 `ON THIS PAGE`。
- 当前可视章节用冰青文字、左侧 2px 指示线和轻微背景突出显示。
- 三级标题以缩进与较低对比度表现；标题过长时最多两行并保留完整 `title` 提示。
- 每个标题生成稳定 slug 与可复制锚点链接；标题元素需设置 `scroll-margin-top`，避免被固定导航遮挡。
- 目录高度超过视口时允许独立滚动，但页面滚动与目录滚动不能互相抢夺。

### 4.5 正文与 Markdown 规则

主正文列宽建议为 680–760px，正文文字桌面端 17–18px、行高 1.85–1.95。正文采用深色透明阅读底层，而不是纯黑或不透明大卡片。

- `h2`：具有充分的上方留白、冰青细线或编号提示；每个标题在悬停或键盘聚焦时显示锚点链接。
- `h3`：不使用过重分隔线，依靠字号、间距与颜色层级区分。
- 段落：单段不宜过宽；长英文、URL、代码标识必须可断行。
- 链接：常态为浅冰青，悬停和键盘焦点时提高对比度并显示清晰下划线。
- 行内代码：使用较深的蓝黑半透明底、圆角 4–6px 和等宽字体；颜色不能使用刺眼的高饱和红。
- 代码块：带语言/文件名栏、复制按钮和横向滚动容器；复制按钮必须有 `aria-label`。代码块不自动换行，窄屏通过横向滚动查看。
- 引用块：使用左侧冰青线、低对比度蓝黑底和可选的“注记 / 提示 / 警告”类型标识；警告使用低饱和琥珀色，而不是高亮红色。
- 图片：正文内图片默认圆角 14–16px；重要宽幅图片可突破正文列至约 960px，但必须保持阅读重心。图片需有 alt、宽高信息、图注和懒加载策略；首屏关键图例外使用高优先级加载。
- 表格：外层包裹可横向滚动的容器，首列可在需要时保持可见；表头使用低对比度深色底和清晰边框。
- 分隔线：仅用于章节级内容切换，避免每个段落后都添加装饰。

### 4.6 文末内容

正文结束后提供连续阅读与回流路径：

- “本文结束”小型标记与最后更新时间。
- 同标签或相关文章，最多 3 张紧凑玻璃卡片；无相关文章时不显示空容器。
- 上一篇 / 下一篇文章导航，使用标题、方向与发布时间，不使用“上一篇”“下一篇”以外的模糊按钮文案。
- 返回文章列表链接，以及低干扰的页尾版权与联系入口。

地球与小猫组件不进入正文列、不跨越代码块或图表。文档页可在页面首段右上角保留静态小地球作为环境标记；滚动进入正文后淡出或停留在非交互区域，默认不播放小猫跨卡片动画。

## 5. 移动端设计

移动端在 `max-width: 760px` 时以单列阅读为唯一结构，不压缩桌面三栏：

- 顶部导航保留品牌、当前页面和菜单按钮；主导航进入全屏或半屏抽屉，触控目标至少 44px。
- 页面边距 16–20px，文章标题 30–36px，正文 16–17px，行高约 1.85；不通过缩小文字换取更多内容。
- 面包屑只保留“文章 / 返回文章列表”，当前标题不在窄屏面包屑中重复展示。
- 阅读时间、日期、标签在标题下自动换行；标签默认横向滚动或折叠，不能挤压标题。
- 目录改为文章头部下方的折叠面板，默认关闭；点击后在当前页面展开，不使用遮挡正文的弹窗。
- 阅读进度改为固定导航底部 2px 细线，或文末返回顶部按钮；不保留桌面左侧工具栏。
- 代码块、表格和宽图各自横向滚动或适度缩放，页面主体不得产生横向滚动条。
- 图片使用全宽容器，保留圆角与图注；图片点击放大时应使用可关闭、可键盘退出且 `overscroll-behavior: contain` 的查看层。
- 相关文章从三列改为单列或横向滚动卡片；上一篇/下一篇为纵向堆叠的完整触控卡片。
- 小地球组件默认静态且尺寸不超过 72px；小猫跑动和跨模块互动默认关闭，用户主动点击后才播放短动画。

## 6. 交互状态、可访问性与性能要求

- 页面顶部提供“跳到正文”链接，键盘聚焦时可见。
- 使用语义化 `article`、`header`、`nav`、`aside`、`main`、`figure`、`figcaption`、`table` 等元素；按钮用于动作，链接用于导航。
- 所有图标按钮提供 `aria-label`；装饰图标使用 `aria-hidden="true"`。
- 所有交互元素具备明确的 `:focus-visible` 状态，不能仅移除默认轮廓。
- 动效遵循 `prefers-reduced-motion`；目录高亮、进度条、卡片悬停和小猫动画必须可中断。
- 目录、筛选、阅读设置等可恢复状态应反映到 URL 查询参数或本地持久化策略；章节锚点必须可直接访问。
- 加载状态使用与文章头部和正文宽度一致的骨架屏；404 显示“文章不存在或尚未发布”并提供返回文章列表按钮；网络错误显示重试操作。
- 首屏背景为 CSS 环境层或压缩后的静态图，不加载大型视频。正文图片启用懒加载、显式宽高和适当尺寸，避免 CLS。
- 文档内容中超过 50 项的长目录、版本记录或大型表格应使用 `content-visibility`、分页或虚拟化策略。

## 7. 建议组件与实现边界

建议在后续实现中建立以下可复用组件：

| 组件 | 职责 |
| --- | --- |
| `ArticleShell` | 提供文章详情页三栏/单栏响应式布局与环境背景层 |
| `ArticleHeader` | 渲染面包屑、类型、标题、摘要、元数据与标签 |
| `ArticleToc` | 生成目录、同步当前章节、提供锚点导航 |
| `ArticleReadingTools` | 返回、进度、复制链接与可选阅读设置 |
| `MarkdownProse` | 统一处理 Markdown 标题、代码、表格、图片、引用和图注 |
| `ArticlePagination` | 渲染上一篇、下一篇与相关文章 |
| `ReadingProgress` | 在桌面工具栏或移动端导航下方显示阅读进度 |

现有文章接口至少应继续提供标题、描述、正文、标签、发布时间和更新时间。目录、阅读时长、字数和前后篇导航可以在页面或受控接口中派生；不得在公开页面暴露未发布文章、私有内容、真实本地路径或管理元数据。

## 8. 验收标准

1. 桌面端可在不离开正文的情况下查看目录、当前章节和阅读进度。
2. 移动端无页面级横向滚动，目录、表格、代码块和图片均可用。
3. 文章标题、正文、链接、代码和标签在深色背景上满足可读性要求。
4. 固定导航不遮挡锚点标题，键盘用户可跳到正文并完成目录导航。
5. 文档页与首页共享深蓝灰、冰青、毛玻璃、细边框和克制辉光，但背景复杂度显著低于首页。
6. 地球与小猫仅作为轻量环境元素，默认不影响阅读、性能和减少动态效果偏好。

## 9. 文章档案列表页（`/blog`）

导航栏点击“文章”后，首先进入文章档案列表页，而不是直接进入某篇文章。该页面负责帮助访客发现内容、理解分类并通过搜索、标签和时间筛选快速进入文章详情页。

### 9.1 页面定位与背景

列表页使用与首页、文档详情页一致的深海军蓝背景、冰青强调色、细边框和深色毛玻璃材质，但背景复杂度保持中等：使用深蓝灰渐层、极弱的星点或模糊天体弧面作为环境层，不使用首页的人物、平原和大尺度电影场景。

顶部继续使用统一的悬浮毛玻璃导航，“文章”以冰青细下划线标记为当前页。页面标题区位于导航下方，左对齐显示：

- 冰青等宽眉题，例如 `ARTICLE ARCHIVE` 或“文章档案”。
- 主标题“文章”，副标题说明内容涵盖技术、产品、影像与个人思考。
- 文章总数，例如“共 24 篇已发布文章”；数量必须来自实际数据。
- 右侧可保留一个小型静态蔚蓝地球环境标记，但不显示小猫跨模块动画。

### 9.2 桌面端结构

在 `min-width: 1100px` 时，页面采用“主列表 + 筛选侧栏”的两栏结构：

```text
固定顶部导航
└── 标题与统计区
    ├── 主栏：精选文章 + 时间排序文章列表 + 分页/加载更多
    └── 侧栏：搜索、内容分类、标签、年份、排序、清除筛选
```

主栏宽度约 780–860px，侧栏宽度约 260px。筛选侧栏在滚动时可吸附于视口，但不得覆盖文章列表或导致滚动冲突。

### 9.3 筛选与分类

筛选功能必须可组合，且筛选状态应映射到 URL 查询参数，以支持复制链接、刷新恢复和浏览器前进/后退。

- **搜索**：搜索标题、摘要和标签；输入框有可见标签或 `aria-label`，占位文本使用“搜索文章标题、摘要或标签…”。
- **内容分类**：默认提供“全部、技术笔记、项目复盘、产品思考、影像记录、生活随笔”等分类。若后端尚无 category 字段，应先以受控标签映射实现，不能假装数据字段已经存在。
- **标签**：显示常用标签；选中后以低对比度冰青玻璃态呈现，支持多选或明确的单选规则。标签过多时提供“展开全部”。
- **年份/日期**：默认使用年份筛选；需要日期范围时再展开日期选择器，避免在首屏堆叠复杂控件。
- **排序**：至少支持“最新发布”和“最早发布”；如后端没有阅读量数据，不展示“最热门”。
- **清除筛选**：仅在有生效筛选时出现，文案为“清除筛选”，并保留结果数量，例如“找到 8 篇文章”。

桌面端筛选控件使用同一组毛玻璃输入、选择器和标签；不使用高饱和色块。筛选变化应同步更新 URL、结果数量和分页位置。无结果时显示明确原因与“清除筛选”动作。

### 9.4 精选文章与普通文章元素块

列表顶部可展示 1 篇最近或人工标记的精选文章，但无精选数据时必须完全隐藏该区域。

精选文章使用横向毛玻璃卡片：左侧为 16:9 封面图或项目图，右侧显示内容类型、标题、摘要、发布日期、阅读时间、最多 3 个标签及“阅读全文”文本链接。封面图需要明确尺寸、圆角与 `alt`；没有封面图时使用低对比度抽象环境缩略图，不显示破损图片占位。

普通文章使用 3 列 × 3 行的紧凑文章网格，默认在一个内容区中展示 9 篇文章；这比大尺寸纵向详情列表具有更高的信息密度。网格在常规桌面宽度下使用等宽三列，卡片高度保持一致、间距统一，并使用低对比度深色毛玻璃底层。

每个普通文章元素块只展示完成内容识别所需的信息：

1. 内容类型或分类标签。
2. 文章标题，最多两行，作为整个元素块的主要可点击链接。
3. 发布日期与预计阅读时间，合并为一行元数据。
4. 最多 2 个高相关标签；其余标签以“+N”折叠。
5. 右下角的细箭头或文章序号，二者只能选择一种。

普通文章卡片不显示长摘要，也不默认显示大缩略图。缩略图仅在文章明确配置封面且其内容价值高时使用，且必须占用固定小比例区域，不能使 9 个卡片的高度失去一致性。详细摘要、更多标签与完整文章信息进入文章详情页展示。

单个文章元素块应提供至少 64px 的可点击区域，并在悬停、触控激活和键盘聚焦时提高边框与标题对比度。整个文章块使用链接语义，不能用 `div` 点击跳转。标题和标签必须处理长文本截断与换行。

### 9.5 分页、状态与文末

文章列表默认使用服务端分页或受控的“加载更多”，不能在数据量增长后一次渲染所有文章。当前页、筛选和排序应写入 URL 查询参数。

加载时使用与精选卡片和普通文章块形状一致的骨架屏；错误时显示“无法加载文章”并提供“重试”按钮；空状态显示“没有符合条件的文章”，同时提供清除筛选入口。

列表底部显示分页、加载更多或“已显示全部文章”的明确状态，并提供归档入口。归档不放入主导航，而是作为文章页的次级发现路径。

### 9.6 移动端

在 `max-width: 760px` 时，页面为单列结构：

- 标题区边距 16–20px，主标题 30–36px；总数与副标题自动换行。
- 搜索框保留在标题下方；分类、年份与排序合并进“筛选”按钮打开的底部抽屉或折叠面板。
- 筛选抽屉具备关闭按钮、清除筛选按钮和 `overscroll-behavior: contain`；所有控件触控高度至少 44px。
- 精选文章从横向布局改为封面在上、信息在下的单列卡片；普通文章网格从 3 列降为单列，不在窄屏压缩成两列。
- 每个普通文章块显示类型、标题、日期、阅读时间和最多 2 个标签；不显示摘要，次要缩略图默认隐藏，以保持触控密度与列表浏览速度。
- 筛选生效后在标题下显示可移除的筛选标签与结果数量；分页和加载更多占满可用宽度。
- 页面主体不得产生横向滚动；图片、标签、长标题和日期范围控件需要主动处理溢出。

### 9.7 验收标准补充

1. 访客可从“文章”导航直接理解站点文章类型、总量和最近内容。
2. 搜索、分类、标签、年份与排序可用，结果和 URL 状态一致。
3. 精选文章展示摘要和封面；普通文章在 3×3 网格中展示类型、标题、日期、阅读时间和标签，不因缺失封面或摘要产生空白破损布局。
4. 桌面端的筛选侧栏与移动端筛选抽屉均不遮挡列表、支持键盘或触控操作，并提供清除筛选与空状态恢复路径。
5. 列表页与首页、文档详情页风格统一，但阅读与检索优先级高于背景效果与地球组件。
