# 作品页面改版：接口、内容模型与后台管理设计

## 1. 结论与依据

本方案以 [作品 UI 设计](前端页面ui设计-作品.md)、四张效果图及当前代码为准，目的是将作品从基础静态条目升级为可筛选、可阅读、可观看、可直接使用且可在后台维护的内容资产。本文件是**拟实施设计**，不表示接口、数据库或后台页面已经存在。

当前事实与差距如下：

| 范围 | 当前已实现 | 本次需新增或调整 |
| --- | --- | --- |
| 公开列表 | `GET /api/portfolio` 返回全部已发布且审核通过的记录；前端只展示封面、标题、简介、标签 | 分页、搜索、类型/媒介/年份/标签筛选、排序、聚合筛选项、卡片能力摘要 |
| 公开详情 | `GET /api/portfolio/:slug` 返回单条公开记录；页面为封面、Markdown 与单外链 | 按类型返回和渲染项目、影像、工具三种详情数据，支持媒体、资源、内容区块、提示词条目、相关推荐 |
| 数据模型 | `Portfolio` 使用 `content/images/link/tags/category` 等字符串字段 | 类型、状态、元数据、媒体、资源、内容区块、提示词条目、排序、版本与受控资产关系 |
| 内容生产 | 内容流水线可生成 `contentType=portfolio` 候选并在审核后创建草稿 | 候选内容须可补充作品类型与结构化元数据；正式作品编辑、预览、送审、发布和撤回 |
| 管理后台 | 已有管理员登录、TOTP、`requireAdmin`、审计日志、内容流水线；没有作品管理接口或页面 | `/admin/portfolio` 工作台和对应管理员 API；所有写操作经 service、校验、权限与审计 |

现有公开查询的 `status=published AND reviewStatus=approved` 是正确安全边界，必须保留并扩展到所有关联媒体、资源、区块和提示词条目。不能把草稿、待审资源、本地绝对路径、私有照片或任意外部 URL 透传给公开页面。

作品内容与后台数据流见：[可编辑 draw.io 源文件](assets/portfolio-management-flow.drawio) 与 [预览图](assets/portfolio-management-flow.png)。

## 2. 对效果图的还原边界

### 2.1 列表页 `/portfolio`

效果图明确了如下不可替换的信息层级：

1. 悬浮深色毛玻璃导航，当前“作品”以冰青下划线定位；标题区在导航下方左对齐，右侧仅保留低对比的静态地球/坐标环境标记。
2. 标题区依次为 `PORTFOLIO ARCHIVE`、大标题“作品”、简短说明、已发布作品计数；不使用首页人物或小猫跨卡片动画。
3. 单条毛玻璃筛选台从左到右容纳搜索框、类型分段按钮、年份下拉、排序下拉和结果计数。它不是拆散成多行的后台筛选表单。
4. 三列等宽卡片网格，卡片封面均为 16:9；类型标识落在封面左上，底部信息区固定呈现标题、两行摘要、至多两个主题标签、日期及类型/能力图标。
5. 卡片按类型展示不同的“可行动线索”：项目展示技术/实验线索；视觉作品显示视频播放或影像记录；工具/仓库可在封面中展示代码或产品预览，并可带独立的复制/打开操作。

桌面内容宽度以 1360px 左右为目标；筛选台与网格左、右边缘对齐。`<1100px` 时网格可降为两列；`<=760px` 时为单列，筛选台收纳为可打开的筛选面板，且所有交互目标不小于 44px。

### 2.2 三类详情页

| 类型 | 效果图的主构图 | 固定信息 | 仅此类型应出现的内容 |
| --- | --- | --- | --- |
| 项目 / 实验 | 顶部“文本信息约 42% + 预览图约 58%”的横向头部；下方主内容与右侧项目事实栏 | 面包屑、类型、标题、摘要、状态、技术/标签、明确主操作、资源、相关推荐 | 背景/方案/过程/结果章节、步骤线、代码块、前后对比、在线演示 |
| 视觉 / 影像 | 先由近全宽 16:9 主画面建立观看语境，信息带压在画面下缘；下方左画廊、右信息与目录 | 面包屑、类型、标题、年份、媒介、主操作、作品信息、资源 | 播放器、章节缩略图及章节时长、全屏画廊、拍摄/创作笔记 |
| 工具 / 仓库 | 左侧为标题与说明，右侧为项目信息；下方是带标签页、分类和搜索的功能控制台，右边为功能导航和资源预览 | 面包屑、用途、更新日期、状态、技术栈、资源、使用说明 | 检索条目、展开/收起、复制、变量说明、示例输入输出、风险提示 |

三类作品共用视觉语言、可访问性、公开安全边界、资源语义与状态语义，但**不得**用一个“大 Markdown 页”模拟三种功能。详情组件应按 `type` 选择主渲染器；区块、媒体和资源为类型专属能力的组合，而不是另一套随意增加的页面类型。

## 3. 公开页面功能与接口影响

### 3.1 列表功能

| 前端功能 | URL 参数 | 后端要求 |
| --- | --- | --- |
| 全文搜索 | `q` | 搜索标题、简介、公开标签、技术栈和类型；不搜索草稿正文或私有字段 |
| 类型切换 | `type=project|visual|tool` | 按结构化 `type` 精确过滤；默认 `all` |
| 媒介过滤 | `media=image|video|gif|code|embed|download` | 按公开媒体/内容区块的聚合能力过滤 |
| 标签多选 | `tag=nuxt,webgl` | 仅接受规范化标签值；返回仍受分页约束 |
| 年份与排序 | `year=2026`、`sort=updated|published|featured` | `featured` 仅为显式精选排序，不能伪造热度；稳定次级排序为 `id` 或发布日期 |
| 分页与恢复 | `page=1&pageSize=12` | 最大 `pageSize=24`；返回总数、总页数与当前筛选上下文 |

筛选、搜索、排序和当前页必须写入 URL，以支持刷新、分享、浏览器前进/后退。前端不得为了显示筛选数量再请求或下载未过滤的完整库。

### 3.2 公开接口契约

所有成功响应保持现有统一外层：`{ success: true, data }`；参数错误或不存在统一为 `{ success: false, code, message }`。公开 DTO 必须由 service 显式投影，不能直接返回 Prisma 实体。

#### `GET /api/portfolio`

请求参数：

```text
q?, type?, media?, tag?, year?, sort=featured|updated|published,
page=1, pageSize=12
```

返回的 `data`：

```ts
{
  items: PortfolioListItem[]
  pagination: { page: number; pageSize: number; total: number; totalPages: number }
  filters: {
    types: Array<{ value: 'project' | 'visual' | 'tool'; count: number }>
    media: Array<{ value: string; count: number }>
    years: number[]
    tags: Array<{ value: string; count: number }>
  }
}
```

`PortfolioListItem` 仅包含 `slug/title/description/type/cover/featured/publishedAt/updatedAt/labels/capabilities/mediaSummary`。其中 `capabilities` 是由已发布数据计算出的白名单枚举，例如 `['code', 'interactive-demo']`、`['video']`、`['search', 'copy']`，不能由访客提交的任意文案组成。

#### `GET /api/portfolio/:slug`

返回：

```ts
{
  item: {
    slug: string
    type: 'project' | 'visual' | 'tool'
    title: string
    description: string | null
    status: 'in_progress' | 'completed' | 'archived' | 'experiment'
    publishedAt: string
    updatedAt: string
    cover: PublicMedia | null
    facts: { period?: string; roles: string[]; techStack: string[]; medium: string[]; location?: string }
    labels: string[]
    primaryAction: PublicResource | null
    resources: PublicResource[]
    blocks: PublicBlock[]
    media: PublicMedia[]
    promptVault?: PublicPromptVault
  }
  related: PortfolioListItem[]
}
```

`related` 最多 3 条，优先同类型且至少共享一个公开标签；不足时按精选和最近更新补齐。详情读取必须再次限定作品及其关联项均为可公开状态，不依赖列表接口已经过滤过的假设。

#### `GET /api/portfolio/:slug/prompt-entries`

仅服务 `type=tool` 且 `toolMode=prompt_vault` 的作品。请求参数为 `q/category/tag/page/pageSize`；服务端对标题、摘要、标签与正文执行检索，但列表响应只返回条目摘要、分类、标签、更新时间与可展开标识，不在首屏返回整个仓库的提示词正文。

#### `GET /api/portfolio/:slug/prompt-entries/:entrySlug`

返回单一已公开条目的正文、变量说明、示例与风险提示，供用户点击“展开提示词”后按需加载。两个端点都必须再次验证父作品和条目为已发布、已审核状态；不匹配工具类型、未公开 slug 或未公开条目一律按不存在处理。

### 3.3 页面与前端数据责任

- `/portfolio` 只依赖列表 DTO，不加载详情完整区块；封面统一指定尺寸和 `loading="lazy"`，首屏精选图例外。
- `/portfolio/:slug` 根据 `item.type` 选择 `ProjectDetail`、`VisualDetail` 或 `ToolDetail`；共享 `PortfolioHeader`、`PortfolioFacts`、`PortfolioResources`、`RelatedWorks`。
- 仅使用服务端批准的区块类型。普通 Markdown 必须清洗后作为 `richText` 区块渲染，不能以 `v-html` 渲染未清洗管理输入。
- 图片全屏、视频播放、复制提示词、展开条目、筛选和分页均使用可键盘操作的按钮；复制结果通过 `aria-live="polite"` 给出文字反馈。

## 4. 作品类型的共用能力与扩展能力

### 4.1 共用字段和区块

每个类型都应支持：标题、slug、摘要、封面、标签、精选、公开状态、时间、角色、技术/媒介、资源、可访问替代文本、相关推荐和版本号。下列区块可跨类型使用：`richText`、`imageGallery`、`quote`、`download`、`resourceLinks`、`divider`。

### 4.2 项目 / 实验扩展

| 能力 | 前端表现 | 数据要求 |
| --- | --- | --- |
| 项目章节 | 右侧锚点和“背景—方案—过程—结果”阅读流 | 有序 `section` / `richText` 区块与稳定锚点 ID |
| 步骤线 | 01/02/03 的横向过程线，移动端纵向 | `timeline` 区块，条目含标题、说明、顺序 |
| 代码展示 | 文件名、语言、复制按钮，可水平滚动 | `code` 区块，代码文本、语言、文件名、行号开关 |
| 对比结果 | Before/After 并排图和图注 | `comparison` 区块，成对公开媒体与描述 |
| 在线演示 | 明确“打开在线演示”或受控嵌入 | `resource.kind=demo`；嵌入仅可使用白名单域名和 sandbox |

### 4.3 视觉 / 影像扩展

| 能力 | 前端表现 | 数据要求 |
| --- | --- | --- |
| 主视觉/播放 | 16:9 poster；点击后才加载或播放 | `Media.kind=image|video`，视频必须有 poster、时长、字幕/说明（如适用） |
| 影像章节 | 三列缩略图、编号、标题、时长 | `mediaChapter` 区块，媒体引用、排序、标题、时长 |
| 全屏画廊 | 逐张查看、关闭、键盘导航 | 图片 alt、尺寸、图注；仅在用户触发时打开 |
| 创作笔记 | 简短正文置于画廊之后 | `richText` 或 `quote`，不把开发类字段强加给影像作品 |
| GIF/动态视觉 | 首帧/海报静态展示，点击播放与暂停 | poster 与原动态资源分开记录；遵循 `prefers-reduced-motion` |

### 4.4 工具 / 仓库扩展

| 能力 | 前端表现 | 数据要求 |
| --- | --- | --- |
| 控制台标签页 | 项目介绍 / 提示词 / 资源；当前标签可链接 | 固定的工具页面视图状态，不将其误存为 Markdown 标题 |
| 分类与检索 | 分类 chip、搜索框和结果列表 | 独立提示词条目的 `category/title/summary/tags/body` 可检索索引 |
| 展开与复制 | 展开正文、变量说明、“复制提示词”按钮 | `PromptEntry.body` 保留换行；`variablesJson` 结构化；展开状态入 `entry` 查询参数或 hash |
| 示例与风险 | 输入/输出预览和风险提示 | 可选 `examplesJson`、`riskLevel`、`usageNote` |
| 模板/下载 | 明确文件类型、大小和用途 | `resource.kind=download`，仅返回受控下载 URL，绝不输出真实磁盘路径 |

工具类可扩展为模板库、资料库或小工具，但首期只实现“提示词仓库”这一 `toolMode=prompt_vault`。未来出现真正需要服务器执行的工具时，必须另行设计权限、配额、输入隔离和审计，不得把远程执行隐藏在当前作品接口中。

## 5. 数据模型设计

### 5.1 建模原则

保留 `Portfolio` 作为作品主实体；将一对多且需要排序、筛选、独立审核或独立编辑的内容拆为关联表。不要把媒体、动作、内容区块和提示词条目继续塞进逗号分隔字符串，也不要把任意结构直接持久化为未约束 JSON。

`metadataJson` 或 `configJson` 仅用于已定义区块的少量可选配置，并在服务端以判别联合（discriminated union）验证后写入。数据库约束无法表达的枚举和 JSON 结构由 Zod 验证器负责；所有枚举常量置于共享领域模块，避免前后端各自硬编码。

### 5.2 拟新增/调整实体

| 实体 | 关键字段 | 用途与约束 |
| --- | --- | --- |
| `Portfolio`（调整） | `type`、`displayStatus`、`publishedAt`、`year`、`rolesJson`、`techStackJson`、`mediumJson`、`location`、`version`、`archivedAt` | `type` 为 `project/visual/tool`；`status/reviewStatus` 延续发布门禁；`version` 用于乐观并发控制 |
| `PortfolioMedia` | `portfolioId`、`kind`、`storageKey`、`publicUrl`、`mimeType`、`sizeBytes`、`derivativeStatus`、`posterMediaId?`、`alt`、`caption`、`width/height/duration`、`sortOrder`、`status` | 记录受控媒体。公开读取只允许 `status=ready` 且父作品公开；`storageKey`、MIME/大小与处理内部状态永不出现在公开 DTO |
| `PortfolioResource` | `portfolioId`、`kind`、`label`、`url`、`external`、`sortOrder`、`isPrimary` | `kind` 为 `demo/repository/document/video/download/article`；外链须通过 URL 策略验证；每件作品至多一个主操作 |
| `PortfolioBlock` | `portfolioId`、`kind`、`anchor`、`title`、`payloadJson`、`sortOrder`、`visibility` | 区块种类仅限本文件定义的白名单；`anchor` 在单作品内唯一；受控 JSON 按 `kind` 校验 |
| `PortfolioPromptEntry` | `portfolioId`、`title`、`slug`、`category`、`summary`、`body`、`variablesJson`、`examplesJson`、`riskLevel`、`sortOrder`、`status` | 仅 `type=tool` 且 `toolMode=prompt_vault` 使用；标题/分类/标签/正文允许服务端全文搜索 |
| `PortfolioPromptTag` | `promptEntryId`、`name` | 规范化提示词标签，支持索引和筛选；与作品标签区分 |

当前 `images`、`link`、`content`、`coverImage` 仅作为一次性迁移输入：分别回填到 `PortfolioMedia`、`PortfolioResource`、`PortfolioBlock` 后立即删除旧列。运行时代码不读取旧列、不保留兼容回退；`tags` 与 `category` 仅在完成后续标签/类型规范化前作为当前模型字段使用，不能替代 `type`。

### 5.3 状态机与可见性

```text
draft(pending) → draft(submitted) → draft(reviewing) → draft(approved) → published
      ↑                   │                    │                 │             │
      └── draft(changes_requested) ────────────┘                 rejected      └→ archived
```

- `Portfolio.status` 表示发布状态：`draft/published/archived`；`reviewStatus` 表示 `pending/submitted/reviewing/approved/rejected/changes_requested`。实施时可将现有 `approved` 默认值迁为 `pending`，避免新草稿被误标为已审核。
- 只有 `status=published AND reviewStatus=approved` 的作品、区块、媒体、资源和提示词项可进入公开 DTO。
- `displayStatus` 是访客可读的作品事实（`in_progress/completed/archived/experiment`），不能替代安全发布状态。
- 删除采用软删除/归档。硬删除媒体、作品或提示词条目仅允许经过显式管理员确认、影响提示和审计记录；不属于首期功能。

## 6. 管理员 API 设计

### 6.1 权限与通用规则

所有 `/api/admin/portfolio/**` 端点先执行 `requireAdmin(event)`；正式发布、撤回、归档和删除使用更明确的角色策略（首期与现有权限常量保持一致，允许 `admin/superadmin`；若未来引入编辑者角色再按资源所有者细分）。所有写入依次执行：认证 → 授权 → 请求体/URL 校验 → `portfolio-service` → 审计日志 → 统一响应。

管理员接口不接受客户端传入的 `createdBy`、`reviewedBy`、`publishedAt`、`storageKey` 或任意 `publicUrl`；这些值由登录身份和受控资产服务生成。嵌入 URL、下载 URL 和资源 URL 必须经过协议、域名白名单与长度校验，拒绝 `javascript:`、`data:` 和内网/回环地址。

### 6.2 端点清单

| 方法与路径 | 目的 | 主要输入/输出 |
| --- | --- | --- |
| `GET /api/admin/portfolio` | 管理列表 | `q/type/status/reviewStatus/page/pageSize`；返回草稿、待审、已发布、归档的摘要和分页 |
| `POST /api/admin/portfolio` | 创建空草稿 | `title/type`，服务端生成初始 slug、版本和审计记录 |
| `GET /api/admin/portfolio/:id` | 编辑器加载 | 返回完整管理 DTO，包括非公开草稿区块及媒体状态 |
| `PUT /api/admin/portfolio/:id` | 保存作品快照 | 基础字段、事实、资源、区块和条目；携带 `version`，冲突返回 `409` 与最新版本信息 |
| `POST /api/admin/portfolio/:id/submit` | 送审 | 服务端执行完整性校验；返回缺失项列表或进入 `submitted` |
| `POST /api/admin/portfolio/:id/review` | 审核决定 | `{ action: approve|reject|request_changes, note? }`，写审核人与审计 |
| `POST /api/admin/portfolio/:id/publish` | 人工公开发布 | 仅 `approved`；再次检查所有引用资源可公开后设置 `publishedAt` |
| `POST /api/admin/portfolio/:id/unpublish` | 撤回公开 | 设为草稿或归档，不删除内容；公开接口立即不可见 |
| `POST /api/admin/portfolio/:id/archive` | 归档 | 终止公开、保留历史和审计 |
| `POST /api/admin/portfolio/:id/media` | 上传/关联受控媒体 | multipart 文件或已存在的受控资产引用；返回媒体记录，不返回本地路径 |
| `PATCH /api/admin/portfolio/:id/media/:mediaId` | 编辑媒体信息或排序 | `alt/caption/poster/sortOrder`；禁止任意改写存储位置 |
| `DELETE /api/admin/portfolio/:id/media/:mediaId` | 从作品解除媒体 | 默认软删除/解除关联；若为封面或区块引用，返回阻止原因 |
| `GET/POST /api/admin/portfolio/:id/blocks` | 读取/新增结构化内容区块 | 仅允许 `richText/timeline/code/comparison/imageGallery/embed`，服务端以 Zod 判别联合校验 |
| `GET/POST /api/admin/portfolio/:id/resources` | 读取/新增作品资源 | URL 通过受控白名单；`isPrimary` 每件作品最多一个 |
| `GET/POST /api/admin/portfolio/:id/prompt-entries` | 读取/新增工具提示词条目 | 仅 `tool/prompt_vault` 使用；正文、变量、风险等级和标签均经 schema 校验 |
| `PUT/DELETE /api/admin/portfolio/:id/prompt-entries/:entryId` | 更新/删除提示词条目 | 写入审计日志；删除前保留发布历史 |
| `GET /api/admin/portfolio/:id/preview` | 已认证预览 DTO | 返回草稿渲染数据，带 `noindex`，不复用公开接口绕过状态门禁 |

对于区块、资源、提示词条目的局部增删改，首期建议由 `PUT` 的嵌套快照在数据库事务中完成；拖拽排序也通过同一快照保存。这样可保证一个区块引用的媒体、资源和提示词排序不会分散成部分成功。媒体二进制上传保持独立端点，避免大文件与编辑 JSON 混传。

### 6.3 内容流水线兼容

现有 `ContentCandidate(contentType=portfolio)` 保留为“导入/AI 生成候选”的入口，不作为作品管理后台的替代：

1. 候选审核通过后，`publishCandidate(..., 'portfolio')` 只创建 `Portfolio` 草稿，并带入标题、slug、摘要、清洗后的 `richText` 初始区块和候选标签。
2. 新建草稿默认 `type=project` 且 `reviewStatus=pending`；管理员必须在作品编辑器确认类型、媒体、资源和公开事实后重新送审。
3. 候选的“已发布”语义应改名或在 UI 中显示为“已创建作品草稿”，防止将其误解为已经公开。
4. 旧候选不会自动转公开；公开动作始终由管理员在作品工作台显式触发。

## 7. 后台工作台设计

### 7.1 登录与入口

无需新增登录体系。复用 `/admin/login`、既有 JWT + HttpOnly refresh session、登录限流和管理员 TOTP；通过后进入 `/admin/portfolio`。在现有后台导航新增“作品管理”，与“文章”“内容流水线”并列，不将公开页面的沉浸式布局搬入后台。

### 7.2 `/admin/portfolio` 列表页

列表是高效率管理界面，不是公开作品墙：

- 顶部：新建作品、导入候选、搜索、类型、发布状态、审核状态、更新时间筛选。
- 表格/紧凑卡片：缩略图、标题、类型、状态组合、最后修改人/时间、精选、预览、继续编辑。
- 分组计数：草稿、待审核、已发布、已归档；审核失败和需要修改必须显眼，不能与已发布混淆。
- 批量操作仅限筛选、导出清单和“批量归档预检查”；批量发布、批量删除不进入首期，避免误公开和不可逆影响。

### 7.3 编辑器

编辑页采用“左侧结构导航 + 中央编辑区 + 右侧发布检查器”：

| 区域 | 职责 |
| --- | --- |
| 顶部操作栏 | 保存草稿、预览、送审、发布/撤回、版本与最近保存状态；危险操作单独放入菜单 |
| 左侧结构导航 | 基础信息、封面与媒体、内容区块、资源、提示词条目（仅工具类型）、SEO/分享、变更历史 |
| 中央编辑区 | 根据 `type` 提供对应表单和区块编辑器；切换类型时展示会失效的专属区块并要求确认 |
| 右侧发布检查器 | 状态时间线、必填项、媒体 ready 状态、缺少 alt、无主操作、外链不合规、审核意见和预览链接 |

类型切换规则必须明确：项目、影像和工具可共享基础字段与普通图文区块；项目专属代码/对比、影像专属章节、工具专属提示词不会被悄悄丢弃。切换前显示影响清单，管理员选择“保留为隐藏草稿区块”“转换为通用区块”或“删除并确认”。

### 7.4 审核、预览与审计

- 审核者先在认证预览页检查桌面与移动视图，再批准或要求修改；预览响应设置 `X-Robots-Tag: noindex, nofollow`，并且不产生公开缓存。
- 发布检查必须阻止：没有标题/类型/slug、无封面或可接受的类型占位封面、媒体未就绪、图片缺 `alt`、主资源 URL 不合规、未审核条目、工具作品无条目或项目/影像核心内容缺失。
- 写审计的动作至少包括创建、保存、媒体关联/解除、送审、审核、发布、撤回、归档、预览失败校验；`beforeJson/afterJson` 只记录必要的结构摘要，不记录大文件、提示词完整正文或密钥。

## 8. 安全、性能与可访问性约束

- 公开服务端查询须在所有关联 `include`/查询上再次过滤可公开状态；不可仅靠前端隐藏字段。
- 资源 URL 采用 HTTPS 白名单或受控本地资产 ID；iframe 额外设置 `sandbox`、`referrerpolicy`、懒加载及文本回退链接。
- 管理上传验证 MIME、大小、像素/时长上限、文件名、内容嗅探和存储键；异步生成封面/缩略图时，媒体只有在 `ready` 后可送审发布。
- 视频/GIF 默认 poster 和用户触发播放；图片、嵌入、相关推荐非首屏懒加载；公开列表采用数据库分页而非内存过滤。
- 所有图片有 `alt`，装饰图使用空 `alt`；所有按钮有名称和 `:focus-visible`；动画遵守 `prefers-reduced-motion`；窄屏的代码、提示词和表格在自身容器滚动，页面根容器不横向溢出。

## 9. 迁移与实施顺序

1. **数据层**：新增 Prisma 模型/字段、迁移、Zod schema、service DTO 与 URL/媒体策略；为旧记录回填 `type=project`、旧标签、旧封面和 `richText` 初始区块。迁移前备份数据库，迁移后执行 `prisma validate` 与回填计数核对。
2. **管理层**：实现管理员 CRUD、受控媒体、编辑器、预览、审核状态与审计；先使用草稿验证，不改变公开页面。
3. **公开 API**：替换列表为分页 DTO，增加详情 DTO；保留旧路由，改用 slug；迁移完成后直接使用新结构，不保留旧字段运行时兼容回退。
4. **公开 UI**：按四张效果图实现列表、三种详情渲染器和移动布局；逐项做视觉比对，使用真实受控素材，不使用长期抽象占位图。
5. **收口**：移除旧字符串字段的写入路径；确认无生产记录依赖后再规划单独迁移删除。回滚时保留新表数据，将公开读取退回旧投影，而不是删除作品内容。

## 10. 验收清单

- [ ] 列表页的导航、标题区、整条筛选台、三列卡片、类型标识和卡片能力摘要与效果图对应；移动端单列且无横向页面滚动。
- [ ] 搜索、类型、媒介、标签、年份、排序与分页均由公开 API 执行，URL 可恢复状态，结果数量准确。
- [ ] 项目、影像、工具三类作品均使用各自主布局，且共同字段/扩展字段不会相互误展示。
- [ ] 影像不自动播放；工具提示词能展开和复制并有可访问反馈；项目代码、步骤线、对比和资源可正确渲染。
- [ ] 未登录访问所有管理员作品 API 被拒绝；`admin/superadmin` 权限与现有 `requireAdmin` 策略一致；所有写入有审计记录。
- [ ] 草稿、送审、审核拒绝、已批准、已发布、撤回、归档在列表、预览和公开 API 中的可见性符合状态机。
- [ ] 公开 API 永不返回本地路径、未审核媒体、私有照片、内部审计信息、草稿提示词或未白名单资源。
- [ ] 新字段具有 Prisma migration、验证、回填和回滚说明；接口、权限、状态转换、URL 校验、公开隔离和移动端渲染均有自动或手工验证记录。
