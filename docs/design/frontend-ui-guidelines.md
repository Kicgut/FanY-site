## 0. 设计前置：先盘点素材，再决定实现方式

每次开始新页面或重做视觉组件前，必须先检查设计稿、现有代码和 `public/` 素材目录，建立一份“素材盘点表”。至少确认以下内容：

- 背景图：文件名、尺寸、比例、主体所在区域、是否已经包含人物/月球/地平线等构图元素。
- 核心主体：例如地球、月球、产品图或人物的实际图片尺寸、透明边缘和页面中的目标位置。
- 动画素材：是否为 sprite，帧数、每帧尺寸、透明留白、运动帧和待机帧的用途。
- 图标与字体：项目是否已有图标、Logo、字体或 SVG 资产可以复用。

如果背景、核心主体、角色或关键装饰素材缺失，先向用户说明需要补充什么、推荐尺寸和放置目录，并暂停涉及该素材的视觉定稿。不得为了“先跑起来”自行绘制与设计稿含义不同的月球、地球、人物或角色，也不得用 CSS 几何图形替代用户明确要求的真实素材。

只有以下情况可以直接用代码实现：布局、间距、边框、毛玻璃、状态点、分隔线、简单通用图标、轨道的前后遮挡关系和交互状态。这些实现也必须基于实际图片的尺寸和位置计算，不能凭感觉叠加第二套主体。

素材确认后再进入编码，并在验收时检查：原图是否被完整显示、透明边缘是否被裁切、sprite 是否按帧拆分、图片 URL 是否返回 HTTP 200，以及页面是否仍然使用了用户提供的素材。

# 前端页面通用 UI 设计指示

本文件是 FanY-site 公开站页面设计、重构和实现的通用约束。具体页面的设计文件可以在本规则基础上增加页面专属要求，但不得与本文件冲突。主页的专属要求见 [前端页面ui设计-主页.md](前端页面ui设计-主页.md)。

## 1. 设计定位

公开站是“电影感作品档案”，不是后台控制台，也不是功能展示面板。访客首先应该看到真实内容、个人身份和创作气质，其次才是工具能力。

页面的设计顺序为：

```text
真实内容与身份表达 → 清晰导航 → 克制的环境氛围 → 必要的工具入口
```

所有装饰都必须服务于内容、层级或交互。不能为了填充空间添加无意义的轨道、数据面板、渐变文字或重复卡片。

## 2. 视觉方向

公开页面默认采用“深空电影感数字艺术 × 个人内容档案”方向：

- 背景优先使用真实场景图、真实照片或项目封面，不使用纯渐变代替核心场景。
- 主色为深蓝黑、蓝灰、雾灰和冷白；冰青只用于行动按钮、状态点、选中线和交互提示。
- 暖金或琥珀只用于地平线、光源和极少量生命感细节。
- 背景场景负责尺度和氛围，文字与真实内容负责信息，装饰组件不能抢夺二者的注意力。
- 参考图中的人物、月球、地平线等内容如果已经存在于背景素材中，页面不得重复绘制。

## 3. 素材规则

### 3.1 目录

主页静态资源统一放在：

```text
nuxt-app/public/images/home/
```

公共页面素材使用绝对 public URL，例如：

```text
/images/home/hero-moonland.webp
```

加入新的主页素材后，必须确认 Git 忽略规则没有误伤该目录，并确认开发服务器可以直接返回 HTTP 200。

### 3.2 图片规格

- 首屏背景：优先 16:9，推荐 3840×2160，WebP/JPG，避免包含文字、导航和按钮。
- 独立球体或装饰主体：推荐透明 PNG/WebP，主体居中，保留透明边缘。
- 文章、作品和影像卡片：使用真实内容缩略图，禁止只用抽象科技贴图作为长期占位。
- 所有图片必须设置 `alt`；纯装饰图片使用空 `alt`，避免屏幕阅读器重复朗读。
- 大图必须考虑压缩、`loading="lazy"` 和移动端裁切。

### 3.3 Sprite 和逐帧动画

如果素材是一张包含多个姿态的 sprite，不应直接把整张图片压缩到小容器中。必须先按帧数拆分、裁掉透明空白并统一帧画布，再使用逐帧图片或 CSS/JS 动画。

动画素材应明确区分：

- 运动帧：用于移动状态。
- 待机帧：用于暂停、悬停或停止状态。
- 状态帧必须由交互状态确定，不能在“暂停”后仍随机播放运动帧。

## 4. 页面结构

公开页面通常采用以下层级：

1. 悬浮式全站导航。
2. 有明确身份和行动按钮的首屏。
3. 首屏内或紧随其后的真实内容入口。
4. 详细内容区和简洁页尾。

首屏不应强制占满整屏。底部要露出下一段内容或内容卡片的一部分，让访客知道页面可以继续浏览。

内容卡片必须有实际信息：标题、摘要、日期、标签、封面、数量或状态。空数据时要显示明确的下一步入口，而不是空白或伪造内容。

## 5. 导航规则

### 5.1 信息架构

主导航只放访客最需要的内容：

```text
首页 / 博客 / 作品 / 影像 / 关于
```

Skills、AI、登录、后台等工具入口放在右侧工具区、账户区或移动端菜单中，不占用主要内容导航位置。归档属于文章内容体系，不单独挤占主导航。

### 5.2 桌面端

- 导航栏位于顶部并保留页面外边距。
- 使用低对比度的灰蓝色透明毛玻璃，不贴满浏览器边缘。
- 左侧为个人标识和站点名称，中间主导航必须真正居中，不能因为右侧工具区宽度导致整体偏移。
- 右侧可以放声音、在线状态和登录按钮。
- 当前项使用细下划线或微弱光线，不使用厚重胶囊高亮。
- 登录按钮是独立的圆角矩形，必须有上下留白，不能和导航栏边界贴合。

### 5.3 移动端

- 使用清晰的菜单按钮和可关闭的菜单面板。
- 菜单项保持足够的点击高度和间距。
- 主导航和工具入口分组显示。
- 不能仅依赖 hover 才能发现重要操作。

## 6. 毛玻璃与颜色

毛玻璃是界面层，不是装饰性塑料面板。统一使用以下原则：

- 背景透明度适中，必须能隐约看到场景，但文字要有足够对比度。
- 采用灰蓝或月球灰，不把所有面板做成纯蓝黑实心块。
- `backdrop-filter: blur()` 应适度使用，并准备无 backdrop-filter 时的可读退化样式。
- 边框使用极细的低亮度灰白线；阴影轻、向下扩散，不制造厚重悬浮感。
- 导航、按钮、状态标签和内容卡片使用一致的透明度、边框、圆角和阴影语言。
- 正文和辅助文字必须保持可读对比度，不能为了“高级感”使用过低亮度灰字。

## 7. 圆形主体与轨迹规则

球体、地球、月球等主体必须以实际图片元素的尺寸和位置为计算基准，不能凭感觉绘制另一套不一致的圆。

如果需要多个视觉关系，必须分离表达：

- 赤道环用于表达地球的自转或空间关系，可以是蓝色椭圆线。
- 赤道环的后半段应被球体遮挡，前半段位于球体上方。
- 角色运动轨迹不应复用赤道环。
- 角色若沿球体边缘运行，应以球体真实圆心和半径计算运动路径，并补偿角色自身尺寸。
- 轨迹需要圆周运动时，优先使用以球心为 transform origin 的旋转动画，避免用四个关键帧拼接出菱形或椭圆。
- 角色朝向必须与切线运动方向一致；必要时对 sprite 做水平翻转或随轨道同步旋转。

## 8. 字体与排版

- 英文标题使用高可读性、轻重量、略紧字距的显示样式；避免过大导致意外换成三行。
- 参考图明确要求两行时，应通过显式换行、受控宽度和响应式字号保证两行，而不是依赖浏览器随机折行。
- 中文正文控制行宽和行高，避免横向过长。
- 英文标签、时间、状态和技术信息可以使用等宽字体，但不能让所有文本都变成等宽字体。
- 标题、正文、按钮和标签之间要有明确层级，不用大量小号全大写标签制造装饰密度。

## 9. 动效与交互

- 动效必须表达状态或空间关系，不能所有元素统一漂浮或弹跳。
- 悬停只做轻微上浮、边框亮度或透光变化，避免夸张缩放、闪烁和遮挡背景。
- 首屏陪伴组件可以包含明确的播放/暂停操作；暂停后应显示待机姿态，而不是继续播放运动姿态。
- 所有动效必须支持 `prefers-reduced-motion: reduce`。
- 按钮要有可见的键盘焦点、正确的 `aria-label` 和明确的动作语义。

## 10. 真实数据与空状态

首页的文章、作品和影像区必须优先读取对应公开 API；不得用静态伪造数据冒充真实内容。

接口失败、数据库尚未初始化或没有公开内容时：

- 页面仍然保持首屏和布局完整。
- 内容区显示明确的空状态或错误提示。
- 提供进入博客、作品集或相册的下一步链接。
- 不将内部错误堆栈、数据库表名或真实路径展示给访客。

## 11. 开发工具与生产工具

测试环境继续使用 Nuxt DevTools。不要为了复制其外观而在开发环境重复渲染自定义调试面板。

生产环境如需要类似的悬浮面板，必须使用项目自定义组件，并遵守权限边界：

- 普通访客只显示延时、返回顶部、刷新等非调试功能。
- 管理员或超级管理员才显示路由、视口、诊断和其他调试信息。
- 调试面板不能显示密钥、token、数据库内容、内部服务器地址或用户隐私。
- UI 权限判断只决定是否展示能力；真正敏感操作仍必须由服务端认证和授权。
- 生产调试面板不应影响正常页面内容、滚动和移动端操作。

## 12. 验收清单

每次页面实现或重构至少检查：

- [ ] 与设计文档和参考图逐项对照，而不是只检查是否能运行。
- [ ] 背景主体、文字、按钮和卡片的相对位置正确。
- [ ] 导航主项真正居中，工具入口没有挤偏主导航。
- [ ] 首屏图片和所有新增静态资源返回 HTTP 200。
- [ ] 桌面端、平板端和移动端没有标题溢出、卡片截断或按钮贴边。
- [ ] 圆形主体的轨迹、遮挡关系和角色朝向经过实际视觉检查。
- [ ] 空数据、API 失败和权限不同状态都能正常渲染。
- [ ] 键盘焦点、替代文本、减少动效和触摸点击区域可用。
- [ ] 开发环境不误显示生产自定义调试面板。
- [ ] 执行 `git diff --check`，并记录构建失败是否属于本次改动范围。
