# 后台页面设计：控制室、内容运营与受限操作

## 实施评审（2026-07-31）

设计的信息架构、状态机与安全边界保持有效，无需改变“概览 / 内容 / 流程 / 系统 / 受限操作”的分组，也不应把 UI 可见性当成权限控制。实施时确认两项必要调整：

1. 控制室不能使用静态演示数值，因此增加只读概览接口，聚合照片待审核、内容待审核、失败/运行任务、访问环境和脱敏审计摘要；接口仍执行管理员认证。
2. 全局搜索在尚无跨资源检索与权限过滤接口前不渲染为可交互的假入口；待该 API 存在后，再加入设计稿中的命令搜索框，避免制造不可预期的交互。

其余实现沿用本文约束：远程环境不暴露高风险执行面板；审核不等于公开；筛选写入 URL；移动端审核使用资源卡而不是压缩表格。

## 1. 目标与边界

后台是“管理空间”，服务于内容处理、审核、资源组织、状态追踪和受控运维；它不承担公开站的内容叙事，也不复用首页的大背景、地球或小猫动效。视觉上与公开站同属一个系统：深海军蓝、冰青重点色、细边框和克制毛玻璃；交互上则应比公开站更高密度、更清楚、更可预测。

后台的首要目标不是炫技仪表盘，而是帮助管理员迅速回答四个问题：

1. 现在有哪些待办、异常或需要人工决定的内容？
2. 我当前能执行哪些操作，哪些操作被权限或运行位置限制？
3. 这次操作会改变什么、需要多久、能否撤销？
4. 操作是否完成、失败原因是什么、下一步在哪里继续？

本设计覆盖后台布局、仪表盘、列表与表单、照片审核、内容流水线、运维/审计和移动端。不会改变服务端权限或公开策略；任何 UI 可见性都不能替代 API 的认证、权限和 `local_trusted` 校验。

## 2. 当前实现与 UI 不足

当前后台由 `nuxt-app/layouts/admin.vue` 及多个 `/admin/*` 页面组成，已经具备角色菜单过滤、移动抽屉、文章/照片/相册/用户/安全/存储/审计/内容流水线/Jobs/AI 与技能/本地高权限等功能入口。

### 2.1 布局与导航

- 侧栏将 11 个以上页面平铺为一个连续菜单，缺少“内容、流程、系统”的认知分组；用户难以判断先去哪里处理待审核照片或失败任务。
- 当前仪表盘只有账户信息卡，无法显示待审核内容、同步失败、运行任务、最近审计或快捷操作。
- 后台左侧是深色，顶部和内容区却仍采用浅色白底，与已确定的冷色深色体系割裂。
- 菜单主要以数字序号区分，缺少模块图标、状态计数和“本地高权限”与普通管理的醒目边界。
- 顶栏缺少全局搜索/命令入口、通知/待办入口和清晰的访问环境状态；远程管理员容易不知道为何某些操作不可用。

### 2.2 列表、审核与状态

- 文章、照片、相册和候选内容页面各自使用不同表格、标签和操作排列，筛选、分页、空状态、加载反馈和批量行为不统一。
- 照片管理的审核、展示状态、可见范围、同步状态和相册归属全部并列在宽表中；信息量大但缺乏“先处理风险/待审核，再编辑属性”的层级。
- 多数状态变更立即执行，缺少统一的变更摘要、撤销窗口、完成后定位与失败恢复入口。
- 内容流水线有正确的“候选 → 审核 → 生成正式草稿 → 单独公开”概念，但状态与可执行动作没有以统一状态轨迹呈现；中英文文案混杂。
- 当前列表的搜索和筛选条件大多不进入 URL，刷新/分享/返回后难以复原工作上下文。

### 2.3 风险操作与说明

- 本地高权限页已说明 remote owner 与 local trusted 的差异，这是正确方向；但该说明仍像技术文档，不能在普通操作入口旁及时解释禁用原因与安全后果。
- 删除、下架、同步、重建缩略图等操作使用的确认方式和风险表述分散，缺少统一的影响范围、可逆性、权限要求、耗时和审计信息。
- 任务/存储/审计页面没有形成“异常 → 查看原因 → 重试/转交/安全退出”的闭环。

### 2.4 移动端

- 现有移动抽屉可打开侧栏，但密集表格在窄屏容易横向压缩；没有为审核、批量处理、筛选或详情提供卡片式替代视图。
- 顶栏动作在窄屏只做局部隐藏，未明确保留最重要的“待办、环境、退出与当前页面操作”。

## 3. 研究结论与设计原则

成熟后台把全局工具放入表格工具栏，行被选中后再展示批量操作栏，并让单行操作进入溢出菜单或少数常用动作；这样既避免每行堆满按钮，也让批量影响范围清晰。[Carbon Data Table 的表格与批量操作规范](https://carbondesignsystem.com/components/data-table/usage/?source=post_page---------------------------)

复杂流程应根据任务复杂度使用独立页面，而不是把多步骤审核、编辑或运维硬塞进小弹窗；移动端不应依赖批量操作，而需在详情页提供关键单项动作。[Shopify 的后台结构与移动端批量操作建议](https://shopify.dev/docs/apps/design/app-structure) [Shopify 移动端说明](https://shopify.dev/docs/apps/build/checkout/delivery-shipping/delivery-options/ux-for-delivery-options)

据此建立如下原则：

1. **先待办、后全量数据**：仪表盘先呈现需要人决定的审核、失败与风险，而非无意义统计。
2. **一页一个主要行动**：页面头部只保留一个主要按钮；刷新、导出、视图设置等放在工具栏或更多菜单。
3. **状态是可解释的工作流**：每个状态都显示下一步、责任和阻塞原因，不能只靠颜色标签。
4. **批量操作延迟出现**：仅选择资源后出现批量栏，明确显示选中数量、影响范围与取消选择；未选择时不占空间。
5. **高风险行为就近解释**：禁用按钮说明缺少的权限；确认层说明影响、可恢复性与审计记录。
6. **深色但非低对比**：后台使用比公开站更稳定的深色实底，毛玻璃只用于顶栏、筛选栏、卡片和抽屉，数据表主体保持清晰。

## 4. 信息架构与全局布局

### 4.1 导航分组

桌面端采用 264px 可收起侧栏、56px 顶栏和可滚动主工作区。侧栏只显示当前用户有权限进入的项目，并按以下组别呈现：

| 分组 | 页面 | 用途 |
| --- | --- | --- |
| 概览 | 控制室 | 待办、异常、最近活动与快捷入口 |
| 内容 | 文章、照片、相册 | 内容资源、审核、发布、归属 |
| 流程 | 内容流水线、Jobs、AI 与技能 | 候选内容、任务运行与受控 AI/Skill 工作流 |
| 系统 | 存储、审计日志、用户与分组、账户安全 | 资产健康、行为追溯、访问管理 |
| 受限操作 | 本地高权限 | 仅 `superadmin + local_trusted` 可见；与普通菜单隔离 |

- 图标只用于辅助识别，每项仍有文字名称。待审核、失败任务等可用小计数徽标，但 99+ 需收敛。
- “本地高权限”以低饱和琥珀色锁形标识，始终位于侧栏底部独立区；远程超级管理员可看到禁用入口和原因，不可见到具体破坏性动作。
- 顶栏从左到右：折叠侧栏/面包屑、全局搜索（可后续实现）、当前环境状态、待办入口、用户菜单。环境状态明确写为“本地受信任”或“远程受限”，不是仅显示角色。

### 4.2 视觉令牌

- 页面底色：`#08111E` 至 `#0B1523` 的稳定深蓝黑，不使用公开站的大面积场景背景。
- 表面：数据工作区 `#0E1A2A`；顶栏、筛选和卡片采用 `rgba(17, 30, 47, .72)` + `backdrop-filter: blur(16px)`；边界 `rgba(148, 184, 214, .18)`。
- 文字：主文字冰灰白、次级蓝灰；操作重点使用冰青，成功偏青绿，警告低饱和琥珀，危险暗红。状态色必须配合文字与图标。
- 圆角 10–14px；阴影只用于浮层与抽屉；表格行分隔线优先于卡片化。
- 字体：系统中文字体；数字、ID、时间、文件名和状态码使用紧凑等宽字体。

## 5. 控制室仪表盘（`/admin`）

仪表盘是操作起点，不是个人资料页。桌面端布局：

```text
页面标题：控制室 / 今日工作概览                 [刷新]
├── 环境状态条：访问环境、角色、最近同步、系统健康
├── 待处理队列（主列）                  ├── 系统健康（右列）
│   照片待审核 / 内容待审核 / 失败任务    │   存储、缩略图、回流、Jobs
│   每行：数量、原因、下一步按钮          └── 快捷动作（按权限）
├── 最近活动 / 审计摘要                   └── 运行中任务
└── 空状态：无待办时给出“当前没有需要处理的事项”
```

- 顶部状态条只显示真实、可行动的信号：`远程受限：删除和技能同步不可用`、`2 个照片回流失败`、`全部服务正常`。没有异常时保持低存在感。
- 待处理队列按风险和阻塞程度排序，卡片点击进入预设筛选后的目标列表（如 `/admin/photos?review=pending`），而非在仪表盘内重复实现审核。
- 快捷动作只显示创建文章候选、导入 Markdown、上传照片、创建相册等可逆操作。高风险/本地操作不出现在快捷动作中。
- 最近活动展示资源、行为、操作者与时间，连接到带过滤条件的审计日志；不显示敏感请求体、真实路径或密钥。

## 6. 通用资源列表、详情与表单

### 6.1 页面头部与工具栏

每个资源页固定采用：

```text
标题 + 一句职责说明                           [唯一主要动作]
筛选/搜索工具栏（搜索、常用状态、更多筛选、排序、刷新）
已生效筛选 token + 结果数 + 清除全部
列表 / 卡片视图
选择后出现批量操作栏
分页、加载、空、失败状态
```

- 标题下的说明解释页面负责范围，如“照片管理只变更展示、审核与可见范围；相册归属在相册管理中完成”。
- 所有筛选、排序和分页同步 URL，后台刷新、返回、复制链接后仍可恢复上下文。
- 宽屏优先数据表；需要视觉判断的照片、相册使用网格/表格切换。复杂编辑进入详情页或右侧抽屉，不把长表单塞进确认弹窗。
- 选中任一行后显示批量栏：`已选 8 项`、安全动作（如“加入相册”“更新可见范围”）、危险动作进入“更多”并需要二次确认；行内操作在批量模式下禁用。

### 6.2 状态与操作反馈

- 资源状态用“图标 + 文案 + 颜色”：例如 `待审核`、`需修改`、`已批准，未公开`、`已公开`、`回流失败`。禁止仅以红绿颜色判断。
- 成功操作给出可定位的轻量反馈，例如“已将 3 张照片加入相册‘北方的雾’”；可撤销时提供短时撤销按钮。
- 失败反馈说明资源、失败原因和下一步，例如“缩略图生成失败：文件不可读取。查看任务日志 / 重试”。
- 长时操作在任务中心显示排队、执行、完成/失败状态，不使用无限 loading；页面离开后任务仍可追踪。

## 7. 照片、相册与内容流水线

### 7.1 照片管理（高频审核页）

照片管理默认打开“待审核”队列而非全部照片。表格列收敛为：缩略图与标题、提交信息、审核状态、可见范围、同步健康、相册归属、更多操作；EXIF、文件名、分组详情放在行展开或详情抽屉。

- 页面右上唯一主要动作为“上传照片”；“重试失败回流”是次级工具栏动作，只在失败项存在且具备权限时出现。
- 预览点击进入右侧照片详情抽屉：中图、标题、标签、审核决定、可见范围、相册归属、回流/缩略图状态与审计摘要；原图只能明确点击并通过既有权限校验后加载。
- 单项审核使用“通过”“需修改”“拒绝”三种清晰动作；`需修改/拒绝`必须填写或选择原因。通过后仍提示“已批准，尚未自动公开”，避免把审核等同于公开。
- 批量审核适合相同、低风险决定；批量改变可见范围、下架、重试等必须显示受影响数量和状态差异，必要时拆成预览清单。

### 7.2 相册管理

- 相册列表用封面缩略图、名称、照片数、可见范围、最近更新与主题标签；主要行动“创建相册”。
- 相册详情采用双面板：左侧“已在相册”按自定义顺序排列，右侧“可加入照片库”支持搜索与多选。顶部永久说明“移出相册仅解除归属，不删除照片”。
- 编辑相册封面、可见性、描述使用右侧抽屉；影响相册内照片可见性的规则必须明确说明，不能让用户误以为会自动改动单图权限。

### 7.3 内容流水线

候选内容页使用显式状态轨迹：`草稿 → 已提交 → 审核中 → 已批准 → 正式内容草稿 → 人工公开`，并为“需修改/拒绝/下架”标记回退路径。

- 状态标签下显示下一步动作和说明；例如“已批准：可生成文章草稿，仍不会公开”。
- 预览、编辑、审核使用独立工作区或大抽屉；只包含一个当前决定的主要按钮，避免在每行铺开 5–6 个按钮。
- 导入、AI 生成、Hermes 处理等来源以只读来源标记区分；所有结果先停留在候选/草稿状态。

## 8. 系统、审计与本地高权限

### 8.1 存储、Jobs 与审计

- 存储页用健康摘要（可用空间、照片数、缩略图健康、回流队列）+ 异常列表；“一致性扫描”说明只读范围、预计耗时和结果去向。
- Jobs 页按运行中、失败、已完成分段，展示任务类型、开始时间、进度、最后错误和可执行的安全操作；对失败任务提供“查看日志摘要 / 重试”而非模糊的“处理”。
- 审计页默认显示最近关键操作，支持资源类型、操作者、行为、结果与时间筛选；详情面板只展示经脱敏处理的影响摘要。

### 8.2 本地高权限

- 远程访问时：以只读“权限说明页”替代操作面板，显示当前环境、不可用能力及“请在本地受信任网络访问”的原因；不暴露具体执行控制。
- 本地受信任访问时：每类高风险操作独立卡片，显示权限要求、影响范围、是否可恢复、审计记录和明确操作按钮。真正删除、Skill 同步或 shell 类操作必须继续由服务端执行 `local_trusted` 校验。
- 危险确认使用两段式：先展示受影响资源与替代方案，再要求输入资源名称/数量或明确复选确认；不能只使用“确定/取消”。

## 9. 移动端设计

- 侧栏改为全屏/半屏抽屉，分组标题可见；当前模块、待办计数、访问环境和退出按钮保持在抽屉内。所有链接触控高度至少 44px。
- 顶栏保留菜单、当前页标题、待办和用户菜单；全局搜索进入独立全屏搜索页，避免挤压工具栏。
- 列表在窄屏默认切换为资源卡：标题/缩略图、最重要状态、更新时间和“更多”菜单。详情抽屉改为全屏页面。
- 筛选进入底部抽屉，显示已选条件、结果预估、应用与清除。批量操作在移动端隐藏或只提供安全的单项操作；高风险操作在详情页执行。
- 表单按章节单列排列，底部固定“保存草稿/保存变更”操作栏；键盘弹出时不遮挡提交按钮。
- 状态说明与错误消息以紧凑可关闭的行内提示显示；不依赖 hover、右键或拖拽完成核心任务。

## 10. 可访问性、性能与验收

- 所有操作使用真实 `<button>` 或链接，图标按钮有名称；键盘焦点清晰，模态/抽屉保持焦点管理与 Esc 关闭。
- 表格列支持排序时说明当前排序；选择框和批量操作栏通过文本播报选中数量与执行结果。
- 只在权限已知后展示动作；前端禁用仅为说明，服务端仍必须再次认证、授权、校验输入并写审计日志。
