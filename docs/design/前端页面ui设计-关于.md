# 前端页面 UI 设计：关于

## 1. 目标与范围

关于页是简短、可信的个人说明，不应重复首页的内容导航、文章归档或作品详情。访客在一屏内应理解“我是谁、关注什么、如何创作、如何联系”；其余内容通过文章、作品与影像页面证明，而不是堆砌经历时间线或技术图标墙。

页面与首页保持冷色电影感、深色毛玻璃导航、冰青强调色与系统中文字体，但背景使用更安静的“夜色地平线 / 稀薄云雾 / 远处微光”场景。它与首页月球平原产生情绪呼应，却不再次使用巨大月球、地球小组件或小猫，避免成为首页的复制品。

本设计覆盖 `/about` 的桌面、移动端与状态约束；后台个人设置页不在本范围内。

## 2. 当前实现与 UI 不足

当前页面位于 `nuxt-app/pages/about.vue`，采用双栏排版：左侧问候标题，右侧简介、三条事实与一个“去读一些笔记”的链接。结构足够轻，但与当前公开站设计目标尚不一致。

- 使用浅色页面和普通边框，与首页、文章、作品、影像已确定的深海军蓝毛玻璃系统割裂。
- 身份介绍、关注方向和 `BASE / FOCUS / STATUS` 已有基础，但没有明确联系方式、外部主页或可用状态的可行动出口。
- 页面只链接文章，不能根据访客意图进入作品、影像或联系；唯一链接不能承担全部后续路径。
- 没有页面背景、内容容器和导航层的视觉层级，页面在大屏上显得像单独的静态说明页。
- 所有事实都固定展示，未定义字段缺失、联系方式暂不公开或长文本时的回退规则。
- 移动端仅从两栏切为一栏，尚未规定标题比例、背景裁切、触控目标、外部链接提示与减少动态效果。

## 3. 设计原则

1. **少而明确**：关于页最多一段身份说明、三项创作关注、三项能力范围和一个主联系动作。
2. **以作品为证据**：不罗列大量履历、评分或空泛标签；每项能力可轻量链接至真实文章、作品或影像。
3. **背景只营造停留感**：背景负责气氛，文字与操作必须位于高对比毛玻璃/暗色遮罩之上；不能让背景抢过内容。
4. **联系是明确行动**：仅在存在真实邮箱、主页或社交链接时显示；没有公开联系方式时显示“暂不公开联系渠道”，不要使用失效按钮。
5. **不制造伪交互**：本页不使用小猫活动、自动环境音、滚动特效或夸张数据动画。

## 4. 页面结构（`/about`）

桌面端在 `min-width: 960px` 采用“身份主叙述 + 简要档案”布局，首屏高度约为 `min(780px, 100svh)`，首屏底部露出联系区域的上缘，提示页面可继续阅读。

```text
固定悬浮导航
└── 深色场景背景（夜色地平线 / 云雾 / 微光）
    ├── 左侧身份区
    │   ├── ABOUT / PERSONAL NOTE
    │   ├── 姓名或站点名
    │   ├── 一句话定位
    │   └── 80–120 字短介绍
    └── 右侧档案卡（深色半透明毛玻璃）
        ├── BASE / FOCUS / CURRENTLY
        ├── 创作关注（3 项）
        └── 可选静态个人照片或抽象环境局部
首屏以下：能力范围（3 项） + 联系区 + 简洁页尾
```

### 4.1 身份主叙述

- 英文眉标使用 `ABOUT / PERSONAL NOTE`，主标题使用姓名或“你好，很高兴遇见。”；不同时叠加两套大标题。
- 一句话定位示例为“开发者、数字创作者与长期记录者。”，内容应由站点实际信息替换，避免使用不可证实的职业头衔。
- 正文限制在 16–22 个中文字符的舒适行宽内，最多两段；超过时应拆分到“创作方式”而非延长首屏。
- 首屏主操作最多一个：有可公开邮箱时为“联系我”；没有邮箱时使用“浏览作品”。次级入口只使用文字链接，例如“阅读文章”“查看影像”。

### 4.2 右侧档案卡

档案卡使用深色半透明毛玻璃、细边框和 20–28px 内边距。每项为“等宽英文标签 + 简洁值”，只显示真实资料：

| 字段 | 展示示例 | 规则 |
| --- | --- | --- |
| BASE | 中国 / Remote | 没有公开意愿时不显示城市或精确位置 |
| FOCUS | Web · Content · Image | 最多 3 个方向 |
| CURRENTLY | Building personal archive | 可选，避免制造长期过期状态 |

卡片下方放置“创作关注”三行：`将复杂流程变得轻盈`、`用图像记录观察`、`持续整理数字档案`。每行最多一条短句，没有必要不添加图标。

### 4.3 能力范围与联系

首屏之后以两块轻量内容收束：

- **能力范围**：3 张低高度玻璃卡，分别为“产品与前端”“内容与工具”“影像与档案”。每张包含一句说明和一个指向真实内容的文字链接；不展示技能百分比、进度条或无依据的等级。
- **联系区**：标题“想聊聊？”、一行说明和单一主按钮“发送邮件”或“访问主页”。外部链接用明确文案和 `↗`；邮箱使用 `mailto:`，不把邮箱图片化。没有开放合作时可替换为“目前以个人项目为主”。
- 页尾保留站点名、版权年份和最少量链接，不重复整套导航。

## 5. 背景、材质与动效

- 背景为独立图片资源，建议 `3840 × 2160` WebP，页面通过暗色渐层叠加后使用。构图选择夜色荒原、安静水面、远处地平线或云层微光；左侧预留较暗、低细节区域给文字。
- 不重用首页巨大月球平原图；可保留相似冷灰蓝、雾气与很弱的暖色地平线，以维持情绪连续。
- 导航与档案卡使用 `rgba(13, 25, 40, .66–.80)`、`backdrop-filter: blur(16px)`、低亮边框；背景内容在卡片外不得降低文字对比。
- 动效仅允许导航进入、卡片 hover/focus 和页面淡入，且只动画 `opacity` 与 `transform`。`prefers-reduced-motion: reduce` 时取消过渡与背景缓慢位移。
- 不使用自动环境音、小猫、地球、轨道、粒子追逐或浮动装饰。它们属于首页环境角色，不能影响关于页的阅读。

## 6. 移动端设计

在 `max-width: 760px`：

- 维持全屏/半屏导航抽屉；关于页当前项仍以细下划线或浅背景提示。
- 首屏改为单列：背景占满可视区，身份文字放在顶部安全区域，档案卡紧随正文而非左右并列。
- 标题为 34–44px，正文约 16px；左右安全边距至少 20px，并考虑 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。
- 背景使用 `cover` 并以 `object-position`/`background-position` 保留地平线；必要时增加底部暗色渐层，不把主体人物裁在文字后方。
- 能力范围三卡单列；联系按钮全宽且高度至少 44px。外部链接在文字中明确标记目的地，不依赖 hover。
- 不加载额外的动画、视频或高分辨率替代背景；优先使用同一张 WebP 的响应式尺寸/`srcset`，首屏背景可设置 `fetchpriority="high"`。

## 7. 可访问性、性能与验收

- 使用一个 `h1`，后续“创作关注”“能力范围”“联系”使用层级连续的 `h2`；提供跳到正文链接。
- 背景图为装饰时使用 CSS 背景或空 `alt`；如人物/场景是叙事内容，则提供具体 alt，不能写“背景图片”。
- 首屏背景预设尺寸并使用高优先级加载；非首屏卡片中的图片延迟加载。背景图应有深色遮罩，正文和操作的对比度符合可读性要求。
- 所有按钮和文本链接具有 `:focus-visible`，外部链接带 `rel="noopener"`；按钮文案具体，不使用“点击这里”。
- 联系方式缺失、简介为空、能力条目为空时不渲染空卡或空标题；显示网络错误时提供下一步而非静默失败。
- 验收至少确认：首屏 5 秒内传达身份与方向；背景不影响文字；只存在一个主要行动；移动端无横向滚动且可完成联系/跳转；减少动态效果下仍完整可读。
