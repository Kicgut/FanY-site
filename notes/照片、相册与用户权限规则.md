# 照片、相册与用户权限规则

本文档是照片、相册、分组和后台管理功能的唯一权限规则来源。`visibility` 只允许使用 `public`、`groups` 和 `private`；旧值 `friends` 仅为历史兼容数据，不得用于新功能。

## 基本对象

- 用户可属于零个或多个分组。
- 照片有一个上传者、一个可见范围，以及零个或多个所属相册。
- 相册有一个创建者、一个可见范围，以及零个或多个分组。
- 照片与相册是多对多关系；照片管理页必须展示全部所属相册，未加入时显示为空。
- 分组可见对象的分组集合保存在 `visibleTo`，格式为 `group:<名称>`。

## 查看照片

照片是否可见只由照片自身决定，不能因用户能进入相册而放宽。

| 照片范围 | 可以查看 |
| --- | --- |
| `public` | 所有人（含未登录用户） |
| `groups` | 上传者、超级管理员，以及与照片分组至少有一个交集的登录用户 |
| `private` | 上传者和超级管理员 |

未发布或未审核通过的照片仅上传者和超级管理员可查看；普通管理员不因管理员身份获得额外查看权。

## 管理照片

“管理”包括后台列表、详情、审核、修改可见性、编辑元数据、加入或移出相册，以及打开原图。

- 超级管理员可以管理全部照片。
- 每个账号都可以管理自己上传的照片。
- 普通管理员可以管理任何公开照片，以及照片分组与自己分组有交集的分组照片。
- 普通管理员不得管理他人私密照片；普通用户不得管理他人照片。

## 查看与管理相册

相册的可见性只决定用户能否进入相册，不决定其中任意一张照片是否可见。

| 相册范围 | 可以进入 | 可以管理 |
| --- | --- | --- |
| `public` | 所有人 | 超级管理员、相册创建者、任一普通管理员 |
| `groups` | 与相册分组有交集的登录用户、创建者、超级管理员 | 超级管理员、创建者、与相册分组有交集的普通管理员 |
| `private` | 创建者、超级管理员 | 创建者、超级管理员 |

普通用户没有相册管理入口或相册管理 API 权限，即使其拥有照片上传权限。

进入相册后，页面必须逐张按“查看照片”规则过滤照片。例如相册属于 A+B，而用户只属于 A，则用户可进入相册、可看公开照片和属于 A（或 A+B）的照片，但不能看仅属于 B 的照片。

## 照片加入相册

- 私密照片禁止加入任何相册。
- 公开照片可加入任何相册。
- 分组照片仅可加入分组相册，且照片分组必须是相册分组的子集：`photoGroups ⊆ albumGroups`。
  - A+B 相册可加入 A、B 或 A+B 照片。
  - A 相册不能加入 B 或 A+B 照片。
- 创建关联时，操作者必须同时有该照片和该相册的管理权。
- 将照片改为 `private` 时，必须在同一事务中移除它与全部相册的关联。
- 修改分组照片的分组时，若现有相册不再满足子集规则，必须拒绝修改（用户先移出不兼容相册），以避免产生不可解释的历史关联。

## 原图与后台体验

- 管理员照片列表的操作列只保留“预览”和“打开原图”；“复制原图”保留在预览弹窗内。
- 预览先使用中图。点击“原图”或“打开原图”必须展示加载状态，并在失败时展示可理解的错误。
- 原图由 ECS 的受控 `/api/photos/file?...&type=original` 接口提供。若原图已回流 Ubuntu，ECS 必须配置并能访问 Ubuntu 原图服务；服务不可用时接口应返回明确错误并写入服务端日志。
