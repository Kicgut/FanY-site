## 原有技术栈

建议保留现有核心栈，不做框架迁移：Nuxt 3 + Vue 3 + TypeScript + SSR，继续使用 Element Plus，但将它主要限定在后台与复杂表单；公开站则建立一套轻量、内容导向的自定义设计系统。
层面	当前实现	建议方向
应用框架	Nuxt 3、Vue 3、SSR	保留；兼顾首屏、SEO、路由与内容页性能
UI	Element Plus + 页面内 scoped CSS	后台继续用 Element Plus；前台改为统一的自定义组件与设计令牌
样式	已有 CSS 变量、响应式布局	扩展为完整 token：色彩、字号、间距、圆角、阴影、动效、断点
字体	系统字体 + 中文字体回退	保留优先系统字体，保证中文阅读清晰、加载轻量
数据与内容	Prisma / Nitro API	前端只通过权限明确的 API 获取数据，私密照片与后台数据不进入公开页面
质量保障	基础构建与类型检查	增加页面视觉回归、键盘操作和移动端检查；后续可加入端到端测试

目前网站已经有不错的视觉起点：蓝绿低饱和色、卡片层次、圆角与模糊导航，以及桌面/移动端两套导航。但样式主要分散在页面中，且没有 components/ 目录；这会导致后续页面越多，按钮、卡片、筛选器、空状态和加载状态逐渐不一致。首页中的 Your Name 也仍是占位内容。
我建议的设计理念是“克制的个人档案馆”，而不是通用 SaaS 后台：
公开站：内容、照片和作品优先。留白充足、阅读节奏舒缓，让人一眼知道“我是谁、有什么内容、下一步去哪”。
相册：视觉沉浸，但不牺牲检索。照片优先展示，筛选、标签、下载和权限提示保持明确且不过度抢眼。
博客与作品：优先可读性。控制行宽、层级、目录、正文图片和移动端排版，减少装饰性干扰。
后台：效率与风险提示优先。操作分组明确、危险动作有后果说明、状态可见、空状态能指导下一步。
交互：所有操作都应有可预期反馈；点击区域足够大，键盘可操作，加载/失败/无数据不能只留空白。
动效：只用于表达页面切换、层级和操作结果；尊重“减少动态效果”系统设置。
落地时，我会先建立公开站与后台共用的基础组件，例如 AppButton、ContentCard、PageHeader、FilterBar、EmptyState、StatusBadge、ConfirmAction，再按“首页 → 博客/作品 → 相册 → 后台”的顺序统一优化。这样能先确定视觉语言，再避免逐页修补造成风格漂移。
当前架构和样式基线可见于 [nuxt.config.ts](E:\\FanY-site\\nuxt-app\\nuxt.config.ts)、[全局设计变量](E:\\FanY-site\\nuxt-app\\assets\\css\\variables.css)、[公开站布局](E:\\FanY-site\\nuxt-app\\layouts\\default.vue) 和 [后台布局](E:\\FanY-site\\nuxt-app\\layouts\\admin.vue)。下一步建议先确定首页与全站导航的视觉方向，并以此建立设计系统。


现有页面的问题主要是：仅有相册入口、未归册照片无法发现；筛选只覆盖名称和单标签；相册详情接口未完整返回 EXIF；灯箱虽有基础切换，但缺少稳定的信息侧栏与序列定位。
新设计采用“相册 / 全部影像”双入口：全部影像可筛选未归册图片；年度、月份、多标签、地点、相机、镜头、构图方向等按层级组织；大图查看器以图片舞台为主，元数据放在可折叠毛玻璃侧栏。这个方向参考了 Lightroom 的相册、元数据与组合筛选方式，以及 Google Photos 的相册封面、筛选和排序逻辑。Lightroom 组织与筛选 Google Photos 相册管理

后台设计参考了 Carbon 的表格工具栏、批量操作栏与行操作分层，以及 Shopify 对复杂工作流和移动端单项操作的建议。Carbon Data Table Shopify 后台结构

## 技术栈设计

结论：原技术栈方向是合理的，能承载上述设计，不需要更换 Nuxt/Vue，也不需要为公开站引入大型 UI 框架。但它目前只能覆盖约 70% 的目标；要完整落地，需要补齐“内容渲染、安全、富媒体、照片查看器、测试”这五层能力。
当前项目实际使用 Nuxt 3.17、Vue 3.5、TypeScript、SSR、Element Plus、Prisma/Nitro，基础很合适。
能力	现有方案	结论与补强
公开站首页、文章、作品、影像	Nuxt SSR + Vue + scoped CSS	保留。建立公共设计令牌与自定义基础组件即可。
后台操作界面	Element Plus	保留，适合表格、抽屉、筛选、表单、确认框。应统一主题与后台组件规范。
深色玻璃视觉、响应式布局	CSS 变量 + 原生 CSS	足够。扩展为完整 token，并用 CSS 优先处理微动效。
地球、小猫与环境互动	SVG + CSS / Canvas + Vue 状态机	足够，不建议视频或重动画库。使用 requestAnimationFrame，并尊重减少动态效果。
音效	浏览器原生 HTMLAudioElement / Web Audio	足够。用户点击后启用，偏好保存在 localStorage；无需音效库。
富文本、项目代码、画廊、提示词仓库	当前 marked、markdown-it 混用	需要收敛：统一为 markdown-it + 受控内容块渲染。代码、画廊、视频、提示词等不能完全依赖原始 HTML。
Markdown 安全	当前 v-html	必须补强。渲染后的 HTML 需要严格净化；不要让可编辑内容直接注入页面。
代码块	基础 Markdown	建议加入 Shiki，用于服务端/构建期语法高亮、文件名和复制按钮。
照片大图与 EXIF	自研灯箱已有基础	可以继续自研，最符合权限、原图按需加载和信息侧栏需求；无需强行引入重型相册库。
GIF 控制	GIF 本身	需要调整实现：浏览器不能可靠暂停 GIF。重要动效应优先转为静音 <video> / 动画 WebP，并使用静态 poster。
作品类型	Portfolio 单一字符串字段	需要结构化内容块与类型字段；提示词仓库、项目实验、视觉影像共用壳，但各自渲染对应主内容区。
后台状态与批量操作	Element Plus 表格	足够。新增统一的 DataTable、FilterBar、StatusBadge、BulkActionBar、DangerConfirmDialog 等业务组件。
质量保障	构建、TypeScript、少量 Node 测试	明显不足。建议补 Playwright、@axe-core/playwright、关键页面截图回归与移动端用例。

建议的最终技术组合：
Nuxt 3 + Vue 3 + TypeScript + SSR
├── 公开站：自定义 Design System + CSS Variables + CSS/SVG/Canvas
├── 后台：Element Plus + 统一后台主题与业务组件
├── 内容：Markdown-It + 受控内容块 + HTML 净化 + Shiki
├── 媒体：原生 img/video + 服务端缩略图/中图 API + 自研查看器
├── 交互：Vue composables + 原生浏览器 API；按需加入 @vueuse/core
├── 数据：Prisma + Nitro API + Zod 输入/内容块校验
└── 质量：Playwright + axe-core + 截图视觉回归
我不建议现在引入的内容：
不迁移 React / Next.js。
不引入第二套公开站 UI 框架。
不引入 Pinia，当前用 composables 已足够管理筛选、查看器、声音与小猫状态。
不引入完整 CMS 或 @nuxt/content；内容主要在 Prisma 中，采用受控结构化内容块更合适。
不用大型动画库作为默认依赖；页面动效以 CSS 和局部 Canvas/SVG 为主。
最优先补强顺序：
设计令牌与公共/后台组件边界。  
统一 Markdown 渲染并处理 HTML 净化。  
定义作品富内容块和 Prisma 数据结构。  
完善照片公共查询、EXIF 返回与自研查看器。  
建立 Playwright、键盘可访问性、移动端和视觉回归测试。
因此，原方案应调整为：保留核心栈，补充少量专用能力，而不是重构技术底座。


## 底部中间小图标放上去会展开，会显示延时，有toggle nuxt devtools和toggle components inspector功能。这是怎么实现的，用的什么工具，对应代码是什么


• 这是 Nuxt DevTools 的悬浮按钮，不是项目自己写的组件。

  - 延迟信息

  对应工具：

  @nuxt/devtools

  项目中可以通过 nuxt.config.ts 控制：

  export default defineNuxtConfig({
    devtools: {
      enabled: true,
    },
  })

  关闭它：

  export default defineNuxtConfig({
    devtools: {
  })

  它的实现代码位于依赖目录中，通常类似：

  nuxt-app/node_modules/@nuxt/devtools/

  或 pnpm 目录：

  nuxt-app/node_modules/.pnpm/@nuxt+devtools-*/

  它只在开发服务器中显示，执行 pnpm build 后的生产页面不会显示。


› 如何在正式页面中显示告诉我，先不要修改代码


• Nuxt DevTools 不能直接在正式生产页面中显示。它只会在：

  pnpm dev

  开发服务器中注入，正式环境的：

  pnpm build
  pnpm preview

  不会显示。

  如果只是想在“正式数据环境”中查看，可以使用内部测试环境运行：

  pnpm dev --host 0.0.0.0

  但不建议把它暴露到公网，因为 Components Inspector 可能暴露组件结构、源码路径和调试信息。

  真正生产环境如果需要同样效果，只能单独开发一个自定义悬浮调试面板；它不是 Nuxt DevTools 本身。
