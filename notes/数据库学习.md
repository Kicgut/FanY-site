## Prisma

Prisma 不是数据库，它是一个数据库操作层（ORM），必须和 SQLite、MariaDB 等数据库结合使用。它们的关系是这样的：
层次关系
文本

编辑



你的应用代码
    ↓ 调用
Prisma Client（ORM 层）
    ↓ 翻译为 SQL
SQLite / MariaDB / PostgreSQL / MySQL ...（真正的数据库）
打个比方：
SQLite / MariaDB 是仓库本身，负责实际存储数据
Prisma 是仓库管理员，帮你管理进出货物，你不用自己跑进仓库翻找
直接用 SQL 操作 vs 通过 Prisma 操作
以"查询所有用户"为例：
直接写 SQL（不用 Prisma）
js

编辑



const db = require('sqlite3');
const result = await db.all('SELECT * FROM user WHERE age > 18');
你需要自己写 SQL 字符串
没有类型提示，写错字段名只有运行时才报错
表结构变更时，SQL 要手动维护
通过 Prisma
js

编辑



const result = await prisma.user.findMany({
  where: { age: { gt: 18 } }
});
不用写 SQL，Prisma 自动翻译成对应数据库的 SQL
有完整的类型提示，prisma.user. 后面会自动补全所有字段
表结构变了，IDE 立刻标红提醒你
Prisma 到底帮你做了什么
表格
事情	不用 Prisma	用 Prisma
建表/改表	手写 CREATE TABLE、ALTER TABLE SQL	修改 schema.prisma，自动生成迁移
增删改查	手写 SQL 字符串拼接	调用类型安全的方法，如 prisma.user.create()
表结构变更	手动写迁移 SQL，容易出错	prisma migrate dev 自动处理
类型安全	无，字段名写错运行时才报错	编译时就报错，IDE 全程提示
数据库切换	不同数据库 SQL 语法有差异，需要改写	Prisma 屏蔽差异，换数据库几乎不用改代码
总结
Prisma 不能替代数据库，它必须搭配一个真正的数据库（SQLite、MariaDB、PostgreSQL 等）一起用
Prisma 替代的是你手写 SQL 的那部分工作——建表、改表、增删改查
你可以把它理解为数据库的"翻译官"和"管家"：你告诉它你想要什么数据，它帮你翻译成 SQL 去数据库里取
所以你的项目中，SQLite 或 MariaDB 负责存数据，Prisma 负责帮你更方便、更安全地操作这些数据。
